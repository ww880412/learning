结论先说
  1. DevBox解决什么全公司共用的 agent 怎么接工单，又不把真凭据放进沙箱。抄哪一处沙箱里只放占位 token，出站代理按请求换成真 token（deploy/helm/devbox/templates/iron-proxy.yaml、docs/architecture.md「Traffic rules」）；学到的经验作为 PR 里的一个 commit 跟代码一起审（harness/src/harness/memory.py）。还要确认10-27 才开源，★268；「内部约 35% 的 PR 由它合并」是 README 自报；本轮没部署。
  2. cedr解决什么多家 agent 的 Skills / MCP 怎么锁版本，多家模型的评审怎么合成一道闸。抄哪一处.cedr/guard.lock 锁住每个 skill 和 MCP server 的工具面，一变 CI 就失败（crates/cedr-core/src/lock.rs、surface.rs、diff.rs）；跨厂商评审合议，报告不够不放行（crates/cedr-route/src/council.rs）。还要确认★65 的公测项目，1.0 前命令和文件格式可能变；本轮没跑过。
  3. HelixHarness解决什么团队把自己的规范和研发流程做成 harness，并且改 harness 之前先评测。抄哪一处一份插件同时出 Claude Code、Codex 两家清单（helixharness/.claude-plugin、helixharness/.codex-plugin），9 个命令从需求走到归档；候选改进先评估再采纳（helixharness-platform/evolution/candidate.py、helixharness-platform/bench/evaluation_contracts.py）。还要确认滴滴金融科技开源，★236；仓库里没有内部使用规模的数字；本轮只看了 README 和目录。

一、本周各方向的新东西

端侧 harness / 工作台

  • 本周发布 · HelixHarness（#255）：10-27 创建，★236，Apache-2.0。插件部分 9 个命令：init、propose、apply、ut、bug-fix、archive、status、update、config（helixharness/commands/），单仓和多仓 Workspace 两套流程（helixharness/workflows/single、workspace）。可选的平台部分给维护者用：看团队用得怎么样，对比 harness 版本，候选改进评估后再采纳（helixharness-platform/evolution/candidate.py、scheduler.py、storage.sql）。使用反馈的数据结构可以直接参考：helixharness-platform/eval/schemas/feedback-schema-v1.json、telemetry_quality.sql。和 #11 TeamAI CLI 互补：TeamAI 管资产分发，它管 harness 演进。
  • 本周发布 · uncut（#263）：11-02 创建，★222，MIT。7 MB 的单文件 harness，只有 4 个工具，不压缩上下文、不截断输出；供应商在输出上限处截断就直接报错退出，不把半截答案当成功。「宁可失败也不静默截断」可以当工作台 CI 模式的规则；代码很小，internal/harness/run.go、session.go、tools.go 一下午能读完。
  • 补报（本周上 GitHub 热榜）· ThinkRail（#259）：JetBrains 孵化，07-08 创建，★6,971，Apache-2.0。围绕 pi 做的轻量 IDE，工作区互相隔离，项目知识用「活的规格」沉淀：每个 app 和包都有自己的 SPEC.md，再由 packages/spec-graph/core/（parse、graph、query、validate）建成可查询、可校验的图。pi 的子 agent、DAG、委派各拆成独立包（packages/pi-subagents/src/definitions.ts 等）。「单日涨 1,156 星」出自转发帖，未核实。
  • 闭源动态：Cursor 的 Agent SDK 已正式发布（Cursor 博客，10-20 发布，上期漏报）。agent 按代码项目组织：提示词是 Markdown，工具是 TypeScript 函数，自带评测和事件回放，可以一条命令部署到 Cursor，也可以自己跑成一个 Node 进程。博客里的例子 kb-reviewer 用团队的经验库检查每个 PR，每条发现都引用对应的经验笔记。
  • 没入库：Hob（★428，MIT），本地跑开源模型的桌面助手，定位偏通用办公，不算 coding agent 工具。

插件 / Skills / MCP（DSH 生态）

  • 本周发布 · MCode Stack（#258）：10-28 创建，★494，MIT，来自你 10-30 的转发。MiniMax Code 团队按人发布自己真在用的 skill 包（stacks/ronny、stacks/jiachen），每个包同时带三家清单：.claude-plugin、.codex-plugin、.minimax-plugin 下的 plugin.json，templates/stack-template 是新增包的模板。企业内部「每位资深工程师发布自己的 stack」可以照这个目录抄。最值得直接借用的一条是 stacks/ronny/skills/subagent-split-check：子 agent 是管理上下文的工具，不是分地盘；只有实测变差、可以并行又能用完就扔、工具或指令互相冲突这三种情况才拆。
  • 本周发布 · DSH Go（#264）：10-25 创建，★4,661，AGPL-3.0，本周 DSH 生态涨星最快。它是 DeepSeek Harness 的安卓客户端，手机本机跑，也能遥控电脑上的 DSH。仓库里自带一个插件市场：market/schema/plugin.schema.json 定格式，market/scripts/check.mjs 做校验，插件从 market/candidates 进 market/plugins，分「候选」和「上架」两段，可以参考成企业插件的上架流程。同期还有 jackwener/DSH-Android（★697，Apache-2.0）。AGPL，只能借鉴设计。
  • 本周发布 · agent-purge（#265）：10-25 创建，★961，MIT。用一份人设统一替换或注入 Codex、Claude Code、OpenCode、pi 等的系统提示词。可抄的是它往各家配置目录写东西的方式：每次写入都留记录和恢复依据，外部改动保留，恢复冲突明确报错（lib/apply.mjs、persist.mjs、footprints.mjs）。定位偏向绕开默认系统提示词，企业用要先看合规。

身份权限与 MCP 网关

  • 本周发布 · cedr（#256）：10-30 创建，★65，Apache-2.0，公测。一个 CLI 管多家 agent，分五块：
    • Route：按 routes.toml 选 agent、模型、推理强度，同样合适时交给额度剩得最多的套餐（crates/cedr-route/src/pick.rs、pool.rs）。
    • Council：每家厂商起一个评审，合并报告，任何 P0/P1 阻断（crates/cedr-route/src/council.rs）。
    • Guard：把 skill 和 MCP server 锁进 .cedr/guard.lock，工具、描述或网络面一变就让 CI 失败（crates/cedr-core/src/lock.rs、surface.rs、diff.rs、risk.rs）。正好对应本周的扩展后门事件。
    • Sync：一份配置编译进各家 agent 自己的文件（crates/cedr-sync/src/emit.rs、org.rs）。
    • Monitor：用量、花费、限额（crates/cedr-monitor/src/limits.rs、pricing.rs）。
  • 本周发布 · safeagents（#257）：Hugging Face 官方，10-28 创建，★59，Apache-2.0。夹在 agent 和模型服务之间的本地代理，任何能改 base URL 的 harness 都能接（docs/ 下有 13 家的接入说明）。每个工具调用过三道检查（src/safeagents/policy.py、guard.py）：
    • 只看请求本身：调用了请求里没声明的工具，或参数里出现对话中从没出现过的主机名，就拦；模型自己之前说过的不算数。
    • atif-scan 检测器：读 /proc/1/environ、取 K8s service-account token 这类行为。
    • 可选的判官模型：只看用户原话、调用和检测结果，不看 agent 的推理，只能加拦、不能解拦。这条规则可以直接用在工作台的审批层。
    • 它补的是「模型 API 层」这个拦截点，和 #236 Tuskira（MCP 层）、#122 agentgateway（网关层）互补。

成本与模型路由

  • 本周发布 · cheap-ag（#261）：10-29 创建，★196，MIT。Claude Code 的 MCP：Opus 只做计划和决策，便宜模型在独立 worktree 里写代码，测试通过才回到用户手上。路由和任务在 src/plan.ts、routing.ts、jobs.ts；「永远在 worktree 里跑、依赖用符号链接共享」的决策记录在 docs/adr/0003-always-worktree-with-symlinked-deps.md；执行前的同意和权限在 src/consent.ts、permissions.ts。「Opus token 少 63%」是作者自报。

代码审查与 CI

  • 本周发布 · tstack（#262）：Theo（t3.gg）10-24 创建，★2,589，MIT。9 个 skill：
    • skills/council：找三家不同厂商的模型评审，循环到一致。可以和 cedr 的 council.rs 对照：一个是提示词实现，一个是代码实现。
    • full-send 和 full-stop：同一套流程，两个停止点（合并，或停在可合并）。适合做工作台「自动做到哪一步停」的开关。
    • leaving-pr-comments：agent 代你发评论时的格式约定。
  • 补报（本周中文圈刷屏）：Anthropic《How the Claude Code team does code review》（10-15 发布，上期漏报）。
    • 大部分评审在开 PR 之前就做完了：让 Claude 跑测试、拿出输出，再由一个上下文干净的子 agent 审 diff。
    • 每个 PR 先过 AI 评审。按风险决定要几个人批：低风险的（文档、文案、feature flag 后的新代码）可以不要人批。「agent 的批准永远不能当人的批准用」。
    • 每次事故都变成评审的评测用例。
    • 文中「合并 PR 翻倍、回滚占比降 40% 以上」是自报，降的是比例，不是回滚次数。

二、旧项目的重要更新（本周发版）

  • OpenSandbox release-1.2.0（#117，10-27）：上期报的 rc 转正式版。凭据保险库端到端落地，凭据值不会出现在任何公开读接口里；新增空闲自动暂停、访问时唤醒（默认关闭）；出站规则可以按端口限定。
  • agentgateway v1.7.0（#122，10-28）：
    • 计量：模型目录带上上下文窗口和能力；按实际服务档位计费；token、成本、缓存命中率、延迟可以按模型或用户拆。
    • 路由：虚拟模型可以调用你自己的路由服务选目标。
    • 护栏：覆盖各家的工具输出，MCP 流量可以用 CEL 过滤。
    • 升级前注意：MCP 会话一律加密，prompt guard 默认检查工具输出，动态后端不能再访问本机回环地址。
  • DeepSeek Harness dsh-v0.2.2-alpha.2（#1，10-28）：可以更新第三方插件包，热更新失败自动回滚。新增三个实验插件：「subagent_oar 工具」把独立任务交给本机的 Codex 或 Claude CLI；「开发者工具-统计」按轮次看上下文、缓存和工具耗时；「变更请求与工作树」让会话跑在独立的 git worktree 里。
  • PipesHub v1.0.0（#109，10-27）：
    • 新增代码图谱和影响分析工具。
    • 用 client_credentials 的应用必须声明自己代表哪个服务账号。
    • 破坏性变更：移除 SAML 和通用 OAuth 登录。
  • codex-security npm-v0.8.2（#192，10-30）：威胁模型可以导出成可交互的 HTML，带源码证据；新增 Amazon Inspector 报告导入。
  • Bifrost transports/v2.4.0（#137，10-30）：新增 Relays，非 LLM 的 API（搜索、OCR 等）也走网关。共用一份存储凭据，按路由计价，费用记到调用方的虚拟 key、团队和客户预算上。
  • LoopX v2.2.0（#20，11-02）：研究证据可以跨版本追溯；有破坏性变更，升级前要先按迁移说明备份。发布说明里写明「注册、保存设置、完成待办都不算投递证明」，可以借来当工作台验收口径的参考。
  • Arize Phoenix v21.0.0（#132，10-30）：默认开启鉴权，标注新增 DECISION、AGENT 两类。
