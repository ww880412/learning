**身份权限与 MCP 网关**
- 本周发布 · [cedr](https://github.com/Sheernox/cedr)（#256）：10-30 创建，★65，Apache-2.0，公测。一个 CLI 管多家 agent，分五块：
  - Route：按 routes.toml 选 agent、模型、推理强度，同样合适时交给额度剩得最多的套餐（crates/cedr-route/src/pick.rs、pool.rs）。
  - Council：每家厂商起一个评审，合并报告，任何 P0/P1 阻断（crates/cedr-route/src/council.rs）。
  - Guard：把 skill 和 MCP server 锁进 .cedr/guard.lock，工具、描述或网络面一变就让 CI 失败（crates/cedr-core/src/lock.rs、surface.rs、diff.rs、risk.rs）。正好对应本周的扩展后门事件。
  - Sync：一份配置编译进各家 agent 自己的文件（crates/cedr-sync/src/emit.rs、org.rs）。
  - Monitor：用量、花费、限额（crates/cedr-monitor/src/limits.rs、pricing.rs）。
- 本周发布 · [safeagents](https://github.com/huggingface/safeagents)（#257）：Hugging Face 官方，10-28 创建，★59，Apache-2.0。夹在 agent 和模型服务之间的本地代理，任何能改 base URL 的 harness 都能接（docs/ 下有 13 家的接入说明）。每个工具调用过三道检查（src/safeagents/policy.py、guard.py）：
  - 只看请求本身：调用了请求里没声明的工具，或参数里出现对话中从没出现过的主机名，就拦；模型自己之前说过的不算数。
  - atif-scan 检测器：读 /proc/1/environ、取 K8s service-account token 这类行为。
  - 可选的判官模型：只看用户原话、调用和检测结果，不看 agent 的推理，只能加拦、不能解拦。这条规则可以直接用在工作台的审批层。
  - 它补的是「模型 API 层」这个拦截点，和 #236 Tuskira（MCP 层）、#122 agentgateway（网关层）互补。
