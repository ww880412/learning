#11

Paddock

Computers and sandboxes for your agents
新发现
coding agent开发者工具开源
是什么
开源（MIT，Go）的自托管工具：在你自己的一台 VPS 上，给每个 AI agent 开一台独立的 Linux 电脑，或一个锁死的沙箱。
解决
agent 要装依赖、跑 Docker、开 GUI 自测，放在本机不安全，用云沙箱又贵、数据不在自己手里。
亮点
每个 box 是完整 Ubuntu：XFCE 桌面、sudo、box 内 Docker（Sysbox）、SSH，预装 Claude Code、Codex、OpenCode、Pi、Kimi 等，用 paddock prompt 派任务，可插话、中断、看事件流。网络可设全放行、全禁止或域名/CIDR 白名单，运行中可改，云元数据地址始终屏蔽。文件系统快照每分钟一次（很忙时 5 分钟），可 resume、fork、回滚；回滚前先自动拍一张，所以能撤销回滚。作者在 PH 评论里说：密钥放在不进快照的运行时路径，回滚不会泄露 key，但目前回滚后不会自动重新注入凭据。有 CLI、Web 面板、HTTP API 和 TS/Python SDK。仓库 10/17 创建，抓取时 5 星，很新。
启发
两点可抄进工作台的执行环境：一是按任务给 box 打标签、设 TTL 和网络策略（如 run-tests 只放行白名单、scrape-docs 全禁），把「这个 agent 能连哪儿」做成任务级配置；二是「回滚前先快照」让回滚本身可撤销，适合给 agent 改坏环境时兜底。前提是工作台的 agent 跑在可快照的 Linux 容器/VM 里，而不是直接在开发者本机。

PulseDev

Click any UI bug on localhost and your AI agent fixes it
新发现
coding agent开发者工具
是什么
macOS 应用：在本地运行的网页上点中出问题的元素、用一句话说要改成什么，交给 Claude Code、Codex、Gemini CLI 或 OpenCode 去改源码，在页面上审 diff 后才写入。

#2

Overmind

Open-source platform for continuous learning
新发现
coding agent开发者工具开源
是什么
给 AI 团队的模型训练平台：把 agent 的生产 trace 变成评测集和训练数据，微调出自己拥有权重的小模型，并和现在用的模型对比。
解决
agent 上线后出错难定位、效果会漂移，而且每个任务都用前沿大模型太贵。
亮点
先扫仓库，生成 agent 的能力图（能力、提示词、工具、任务），再把 OpenTelemetry trace 打分并归到对应能力上；eval 绑定在线上 trace 上，随代码更新。「优化器」在你的仓库里跑提示词、工具和控制流实验，胜出方案以 git diff 交付。SDK/CLI 是 MIT，平台 AGPL-3.0 可自托管；有给 Cursor、Claude Code、OpenCode、Codex 用的 MCP server。抓取时 714 星。
启发
「从仓库扫出 agent 能力图，再把每条 trace 挂到能力节点上」适合工作台做 agent 可观测：按能力看失败率，而不是翻一长串日志。「优化结果是一份 git diff」也值得抄，让改进走正常代码评审。前提是 agent 的调用已经接了 OpenTelemetry 之类的 trace。

新发现

是什么

See which AI agent is heating your Mac and cool it down.
新发现
coding agent开发者工具效率
是什么
Mac 刘海/菜单栏小工具，显示芯片温度，以及是哪个 AI agent（Claude Code、Codex、Cursor 等）在让 Mac 发烫。
解决

启发
「按 agent 会话归并进程树」可以直接搬进工作台的运行面板：每个 agent 一行，显示它拉起的进程、CPU 和遗留的 dev server，会话结束时提示清理。前提是工作台启动 agent 时记下进程组或会话 ID，否则只能像它一样按进程名猜。
