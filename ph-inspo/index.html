#5

Skillbox

One library for your AI skills, synced to every agent
新发现
coding agent开发者工具效率
是什么
一个管理 AI 技能（SKILL.md 这类说明文件）的桌面工具：所有技能放进一个库，只把需要的那一小部分同步到 Claude Code、Cursor、Codex 实际读取的目录，可以按项目分配。
解决
技能散在 GitHub 仓库、项目文件夹和各工具自己的目录里，同一个技能在 Claude Code 装了、Cursor 没装，队友手里的版本更新了也不知道，说不清哪个 agent 用的是哪一版、安不安全。
亮点
官网称：①「收藏」和「启用」分开——库里存多少都行，只把启用的小集合交付给工具，因为每个加载的技能都占上下文；不用的会自动暂停、重叠的会提示；②从 GitHub/GitLab 加的技能保留来源，上游改了先显示 diff，由你决定接不接，不会悄悄覆盖本机已改过的版本；③每个版本同步前都扫一遍提示注入、数据外泄、硬编码密钥和混淆代码（用 Cisco Skill Scanner，结果按 STRIDE/OWASP 标注），带可执行脚本的技能要你单独同意，放行只对那一个版本有效，下个版本要重新审；④会话做得好时可以让 agent 把方法存成技能，并帮你去掉只属于这次对话的路径和私人信息；⑤Trim 把测试、git、构建的冗长输出截短再给 agent 读，PH 评论里作者说命令失败时完整输出存在本机、agent 一条命令就能取回。还有团队共享库。PH 标「Free Options」，没找到公开源码仓库。PH 评论里作者承认不会按当前打开的仓库自动切换技能，只能把技能分配到某个项目文件夹；有人问多个 worktree 规则不同怎么办，未见回答。
启发
工作台的技能/规则分发可以直接抄三点：①「库」和「启用集」分两层，按项目只下发需要的，控制上下文占用；②技能跟着来源走，上游更新先出 diff 再决定，不覆盖本地改动；③安全放行绑定到具体版本内容（例如按文件哈希），内容一变就重新审，带脚本的单独授权。前提是工作台统一掌握每个 agent 读技能的目录，并给每个技能记来源和版本哈希。Trim 的「失败时保留全文、给 agent 一个取回命令」也适合放进工作台的命令输出层。

#2

Nod by n8n

Open source personal agent with its own computer
新发现
AI工具效率开源
是什么
n8n Labs 出的开源个人 agent（研究预览版，独立于 n8n）：在你的 Mac 或 Windows 电脑上开一台本地虚拟机和浏览器，替你在 Gmail、Slack、Notion、日历和没有 API 的网站上把事办完，比如催发票、取消试用、准备会议。
解决
聊天式 AI 只会告诉你怎么做、不替你做；而能真动手的 agent 又让人担心它乱发、乱付、被网页里的指令带偏，或者把数据放在别人的服务器上。
亮点
官网和 README 称：①权限检查放在服务端而不是提示词里——每个应用动作、每个会改东西的网页步骤，都由一个独立检查对照你的原话和规则，没覆盖到的发送、付款、预订、删除先等你点头（官方承认这个检查本身也是模型、会出错）；②网页、邮件、应用返回的内容一律按「数据」标给模型，不当指令；③密码、验证码、银行卡由 Vault 在网页上私下填，模型看不到，模型服务的密钥也不进沙箱和浏览器；④每个动作、登录、用卡和每个任务的花费都记在 Usage 里，API 模型可设月度上限；⑤自带定时和盯梢任务；可选 20 多家模型或 ChatGPT Plus/Pro 登录。技术栈 TypeScript/Node.js 24、Fastify、PostgreSQL + pg-boss、Pi agent runtime、agent-browser、Composio、MCP、Electron。Apache 2.0，GitHub 约 600 星，11/11 发了 v0.6.2。PH 首帖称在模拟环境里 226 个任务跑 678 次完成 98%、没做过未经批准的发送和付款，这是厂商自测。电脑睡着时不运行，暂时也不会打电话；一个 Nod 目前只有一个主人。团队在 PH 评论里直接点名 Grok Bot 作对比。
启发
和我们自己用的 Grok Bot 是同类竞品，但开源，正好拆来看工作台的「动作审批」怎么落地：①把「这一步是不是用户要的」做成服务端的独立检查，对照用户原话而不是靠主 agent 自觉；②外部内容统一打上数据标记再给模型；③凭据由专门的填写器处理、永不进模型上下文和沙箱；④每个动作和花费落一条审计记录并有预算上限。前提是工作台的所有外部动作都经过一个统一网关，才能在那里放检查。代码 Apache 2.0，可以直接读它 server 里 trust check 和 Vault 的实现。

#7

Relay

DocSend for AI agents: send and receive docs with context
新发现
AI工具效率
是什么
一个「带背景发文档」的分享服务：发提案、方案或合同时，文档给对方本人，你选定的背景说明（为什么这么定价、排除了什么、还有哪些没定）给对方的 AI，对方和对方的 AI 都能就此提问。
解决
现在别人收到文档后，常常先让自己的 AI 读；AI 只看得到页面上的字，看不到背后的取舍，要么答错，要么还得再约一次会来解释。
亮点
官网称：一句「relay 什么 给谁 为了什么」就能发出；发前你同时审文档和背景，并标出哪些话题必须回到你这里（例如折扣、日期），对方的 agent 只能照你批准的背景解释、不能替你拍板；对方转给第三人（如 CFO）时背景一起走，新访问要你一键批准；可随时改文档或背景生成新版本、对方只看到最新版，也能撤销访问（已保存的副本收不回）；也能反过来请对方的 agent 准备材料发给你。PH 评论里团队说每个 relay 有活动页，显示谁的 agent 读了、看了哪些页、问了什么；但对方在自己的 ChatGPT 或 Claude 里读时，只看得到读取和回传给你的内容，看不到对方的私聊。有 MCP server（relayto.ai/mcp），90 天免费试用，不开源。
启发
工作台里 agent 之间交接任务可以抄这个分层：交付物本身之外，单独附一份「决策背景」（为什么这么做、排除了什么、还没定什么），再加一张「必须回问人的清单」，接手的 agent 遇到清单里的事只能退回、不能自己定。前提是交接格式里有放背景和待决项的固定位置，并能记录每次回答基于背景的哪个版本（PH 评论里有人问 Relay 这点，未见明确回答）。

#3

CALL-E

Make phone calls with your AI agent (Muse, ChatGPT, Claude)
新发现
AI工具效率
是什么
让 AI 助手替你打电话的服务：在 ChatGPT、Claude 等助手里说一句要办的事（订位、改预约、问报价、问库存），它补问缺的信息、给你看通话计划，你确认后拨打真实的美国或加拿大号码，回来给你结果和全文记录。
解决
很多事最后都卡在「得打个电话」：按菜单、排队等待、留言回拨，人总是一拖再拖。
亮点
官网称：固定三步「计划 → 确认 → 拨打」，不确认不拨；能听电话菜单按键、在线等待、处理语音信箱；每次结果附全文记录、依据和置信度标签。开发者可以用一句提示在 Claude Code、Codex、Cursor、OpenClaw 里装官方 `calle` 技能，或用 MCP、TypeScript/Python SDK 和 REST API；可以给一个通话目标定义结果的 JSON 结构，每通电话按这个结构返回字段（PH 评论举例：前一天确认演示预约，返回是否确认、改约时间和备注，再写回 HubSpot）。PH 评论里团队说有预检查防止通话中编造信息或未经你同意做决定。只拨出不接听；本地号码只有美国和加拿大，其他国家的号码目前主要用于开发测试；新用户 100 个免费额度。不开源。
启发
两点可借：①所有对外动作走「先出计划、人确认、再执行」三段，计划里写明这次能谈什么、不能答应什么；②让调用方给任务定义返回的结构（JSON schema），执行端按结构回填字段并附原始记录作证据，比让下游再去解析文字可靠。工作台里给 agent 派外部任务时可以照搬这个契约。打电话本身在国内用不上。

#9

Co-Review

Read the whole repository with the agent that built it
新发现
coding agent代码评审开源开发者工具
是什么
一个独立开发者做的开源「代码评审桌面应用」（基于 Eclipse Theia）：把整个仓库、一次改动、别人的 PR 或一份设计稿都打开成评审页，你在行、函数、文件或文件夹上留评论提问，由写这段代码的 coding agent 在评论串里回答。
解决
用 coding agent 写了几个月，每个 diff 看着都没问题，但整个代码库已经不在自己脑子里了：不知道东西放在哪、为什么这么做；逐个 diff 评审补不回整体地图。
亮点
官网称：①整仓审计——agent 先写一份导读（地图、术语、流程、模式和命名、薄弱点），按区域给出待你接受或驳回的发现，每章附一个自测问题；②「已读覆盖率」按区域统计你读过哪些文件，文件被改动后自动回到未读；③评论锚定在代码行上，代码后续改动时评论跟着走并提示「已变化」；④PR 评审在独立 worktree 里检出快照，结论作为一条带行内评论的正式 review 发回 GitHub；⑤设计先行：agent 写 L1/L2/L3 三层步骤树加 Mermaid 图，你评论到具体节点，它修改后只实现你批准的部分。所有 agent 通过 `co-review mcp` 接入，Claude Code 有插件（带后台回答评论的子代理、会话启动时告知待答问题的 hook），Pi / Oh My Pi 有原生包，Codex、Cursor、Gemini CLI、OpenCode 等走 MCP。PH 评论里作者说导读首行写明对应的 commit，事实按 commit 缓存，线程里的回答则按提问时的代码实时读；评审数据存在 ~/.co-review/ 下的 JSON 和 Markdown，不往仓库里写文件。MIT 许可，无账号、无遥测；GitHub 星数还很少，项目很新。
启发
工作台可以抄三点：①把「人重新掌握 agent 写的代码」做成一个正式环节，而不只是逐 PR 审：定期生成整仓导读 + 按区域的已读覆盖率，文件变了就回到未读，管理者一眼看出哪些区域没人真正读过；②评审意见锚定到行并随改动迁移，回答标明基于哪个 commit，过期就提示重问；③「设计树先评、批准的节点才实现」可以直接做成工作台里大任务的默认流程。前提是工作台能拿到每个 agent 的会话并把评论实时推回去（Co-Review 用的是 MCP + Claude Code channels）。仓库 MIT，可以直接拉下来试，看它的 MCP 工具定义。

#5

Seldon（Wren）

Behavioral QA agents that use your product like customers do
新发现
测试AI工具开发者工具
是什么
Seldon（做人类行为模拟的研究公司）推出的 QA agent Wren：用一两句大白话写清从哪开始、要做什么、怎样算通过，它在真实浏览器里并行跑端到端测试，像真实用户一样边看边决定下一步。
解决
Playwright 这类脚本化端到端测试要一步步写死操作，维护成本高，而且只覆盖开发者想得到的路径；用户真实会走的歪路（结账走到一半回去改地址、支付失败重试）往往上线后才暴露。
亮点
官网称：测试用自然语言定义（展示为 YAML），由 Seldon 的行为模型引导每个 agent 下一步尝试什么，所以一条用例可能跑出你没写过的新用例（例：点「加入购物袋」没反馈、用户再点一次，购物车里变成两件）；每次运行有逐步录像、失败证据和复现步骤。价格按完成的运行计：每次 $3（含模型和浏览器费用、无席位费），前 10 次免费，因 agent 或平台故障没跑完的不收费。目前只支持 Web，原生 App 在做。PH 评论里团队承认：「运行前不要提交扣款」这类指令不能保证硬拦截，碰真钱要用只能动测试资金的账号；跑完不会自动清理测试数据，要自己写成步骤或用一次性账号。官网称模拟用户与真人在整段旅程里 87% 的情况下选择一致，这是厂商自测。PH 页显示带 MCP server。不开源。
启发
工作台的「agent 改完怎么验收」可以借两点：①验收用例用「起点 + 目标 + 通过标准」三段大白话写，由验收 agent 自己探路，比让 coding agent 写一堆 Playwright 脚本更不容易和实现一起出错；②每条失败必须带录像和复现步骤，作为退回给 coding agent 的输入。前提是有隔离的预发环境和测试账号，且要接受探索式测试结果不完全可重复；涉及写操作或付费的流程要靠环境隔离而不是提示词来兜底。
