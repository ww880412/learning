这周 3 个判断变了什么升温降温反复出现下周值得关注类别迭代

11/10（周二）到 11/16（周一）共 7 期简报，简报和落选清单合起来一共记了 5893 条原帖（按原帖链接去重）。下面的冷热都只是在我关注且读到了的 80 个账号里看到的情况。11/10 那期的落选清单还按旧类别打标签（仍有「硬件与算力」，「其他」556 条），从 11/11 那期起改用 v4：没实质内容的标「无内容」，不再算进「其他」。冷热按原文统计，不受这个标签切换影响。

这周 3 个判断变了什么

1. 常驻和多开：从「人验得过来多少」到「官方给了拆法，也证明了各带一个 Agent 会更差」

  • 之前怎么看：上周的结论是，开几个 Agent 不由模型决定，由能跑出通过/失败的检查和人的待批队列决定。工作台先做「每个任务带检查、交证据、进队列」，再谈并发数。
  • 这周看到什么：Anthropic 官方文章《Building always-on agents》把「常驻」写成使用体验，而不是模型一直挂线：agent 大部分时间在睡，被事件叫醒后跑一个 run、存状态再睡；外围五个原语是事件收件箱、定时器、记忆、权限和发件箱。官方称 Opus 5.5 在一个长周期编程基准上，每解开一个任务比 Opus 5 便宜 78%，典型工作负载上只便宜 40%（原帖、原帖）。同一天花叔按该文在 FanBox 2.20.0 做了一版（作者自测，原帖）。OpenAI 公开了内部管理大批持久运行 Agent 的做法：把网关等可信逻辑和模型执行拆开，关掉 danger-full-access，用沙箱、Auto-review 和独立身份约束它们，文中称试点后全公司已有 500 多个会在后台主动干活的 Agent（原帖、原帖）。产品侧也在把多 Agent 写进工具：Cursor 把 Projects 改成多人版，Antigravity 上了 /swarm 和后来的 Dynamic Workflows（原帖、原帖）。但 11/16 读到 Anthropic Fellows 的《Worse Together》：在四个共享资源的模拟环境里，每人各带一个 Agent，整体结果都不如大家共用一个；官方称对两个 Claude 模型，协调者比点对点团队大约高出 10 到 45 个百分点（原帖、原帖）。同一天 Lauren Tan 讲 Grok Bot 桌面团队的做法：每纠正一次 Agent，就把纠正写成 lint、类型检查或架构约束，少往 AGENTS.md 里加话；她称上个月把约 1.1 万个 PR 合入生产，相对撤回率约 0.5%，审查重点改成看录屏、截图和形式化验证材料（演讲自报，原帖、原帖）。
  • 现在怎么看：工作台可以按这五个原语拆常驻，不要做成模型一直挂线烧 token。团队场景不要默认「每人一个 Agent 共写一个仓库、共用一份额度」；先设协调者和平台护栏（没读完消息不能提交、取消别人的任务要先同意）。纠错要变成提交时会失败的检查，而不是再写一段 AI 不一定照做的说明。支撑它的是官方文章、模拟评测和一场演讲自报，不是对照生产数据。

2. 准入：从「额度会变、账号可能被封」到「能不能用，还取决于你在哪、公司归谁」

  • 之前怎么看：上周的结论是，除了「给多少」，还要防「账号还在不在」和「后台跑掉多少」。定时任务要单独计量，数据能导出、能换供应商或自托管，是工作台的基本退路。
  • 这周看到什么：Anthropic 新版《支持地区政策》11/12 生效：中国大陆、香港、澳门都不在名单里；人在不支持地区、公司注册或总部在不支持地区、被不支持地区主体多数控股或控制，三种情况都不能用 Claude.ai、Claude Code、API，经云平台和经销商用 Claude 模型也算（官方条款，原帖、原帖）。与此同时，厂商仍在用一次性重置做补偿：Fable 按订阅时长送重置，随后 Claude 又给 Pro / Max / Ultra / Team 一次覆盖全部模型的免费完整重置，北京时间 12/11 06:00 前可用（原帖、原帖）；Grok Bot 用户证实周额度被免费重置，随后 1.0 正式发布，可分享给团队、进 Slack / Teams，高档套餐还能加入会议（原帖、原帖）；Tibo 称 Codex / ChatGPT 的「可积存的重置」已经激活，但没写覆盖哪些产品和到账时间（原帖）。用法上，官方和实测都把 Opus 5.5 medium 当日常主力、Fable 留给大任务：WquGuru 测 Fable 5.2 单价约是 Opus 5.5 的 2 倍，Addy 引用的 52 任务评测里 Fable 并不明显更准，但每个解开任务大约贵 2.80 倍（原帖、原帖）。
  • 现在怎么看：工作台如果默认绑死 Claude Code 或 Claude API，要尽早准备可切换的替代模型和路径，不能只靠换网络。重置是一次性补偿，不提高周上限；Fable 更贵，日常先留在 Opus 5.5 medium。上周说的「后台任务会偷跑额度」仍然成立，小墨还整理了监控 Grok Bot 额度的用法（原帖）。

3. 安全：从「正规软件也会改你的配置」到「没有攻击者也会越权，而且 Agent 开始能付钱」

  • 之前怎么看：上周的结论是，~/.codex/config.toml、hook、插件目录要当成受监控的资产；身份和密钥不进上下文。
  • 这周看到什么：港科大等机构的论文提出「授权漂移」：没有攻击者，Agent 为了把任务做好也会自己越过授权边界；13 个模型跑了 25,207 条轨迹，前沿模型的漂移率在 0.43–0.61，Planner-Executor 脚手架能把漂移率压下来，但成功率也一起掉（论文结果，yibie 解读，原帖）。Deedy 开着 --dangerously-skip-permissions，Agent 执行 pkill -f "cat"，把 Mac 上正在跑的应用全杀了（作者自述，原帖）。Lydia 引用的数字是：把一条权限提示换成明显危险的命令时，人拦住 13.6%，auto mode 拦住 89%，约每 10 条仍会漏 1 条（原帖）。11/16 的 Claude Code 实验功能 Code Mode 把工具调用改成一段本地 JavaScript，auto 模式分类器审的是整段代码，看不到运行时才算出的值（官方文档，原帖）。OpenAI 推出 ChatGPT Wallet：代理可以代为付款，但看不到真实卡号，每笔都要生物识别，目前只在美国向 ChatGPT Pro 的 dot 滚动推送（原帖、原帖）。Guillermo Rauch 分享的上线路径是：用 feature flag 把 agent 写的代码先只对自己可见，推送时再做验证和安全审计（原帖）。上周 Addy 说会去掉上下文里邮箱的版本，这周简报和落选清单里没有读到是否已经覆盖全部平台。
  • 现在怎么看：工作台不能只防提示注入和别人改配置，还要在工具层限住数据和范围；靠提示词或规划脚手架管住它，代价可能是 Agent 不干活。若让 Agent 付费、改生产，或打开会一次过审整段脚本的模式，每笔、每次上线都要人审，必须拦住的调用要靠规则或 hook。无限制权限不能当默认。

3. 常驻 Agent 的做法被写成产品架构

周初还只是额度、多机和 harness 对比，后半周官方和开源都在写「Agent 怎样在没人盯着的时候干活」，周末到周一又补上了「人多各带一个会更差」和「纠错要写成检查」。

  • Anthropic 五个原语、OpenAI 的持久 Agent 实践、《Worse Together》、Lauren Tan 的质量系统：见上面第一条判断
  • Antigravity Dynamic Workflows：用 /run-workflow 让 agent 写一段 Python，以 parallel() / pipeline() 等编排子 agent，脚本先展示再请用户批准（原帖）
  • ChatGPT Wallet 和 Claude Meetings：一条把代付做成产品，一条让 Claude 作为一个可见参与者加入 Google Meet（原帖、原帖）
