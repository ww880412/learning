今日主线
  1. Cursor 母公司 Anysphere 对美国国会说，计划「探索」淘汰中国开发的开源权重模型：众议院国土安全委员会与中国问题特别委员会 11/20 联合报告所载，是探索性计划，委员会没写最终决定和时间表（报告原文，CNBC 同日报道；本期没读到 Cursor 自己的声明）：报告写 Composer 2 建在 Moonshot AI 的底座模型上，这一点是外部开发者查出后才公开的；CNBC 补充 Composer 2 基于 Kimi K2.5，SpaceX 8 月完成收购 Cursor。报告 12 条建议里包括：禁止中国开发的模型用于联邦系统和联邦合同工作，并从高风险关键基础设施功能中移除（众议院新闻稿、报告 PDF、CNBC、Nathan Lambert 评论）
    前提或争议：报告发布前流传的转述写成「所有」中国开源权重模型，报告原句是「探索」淘汰；Nathan Lambert 认为这是把政治风险拼错了，这是他的个人看法
    为什么值得看：做企业级 coding agent 工作台，客户若涉及联邦合同，底座模型的出处会被要求可披露；报告也提到微调、蒸馏会让出处变模糊，工作台最好记录每个模型的来源
  2. Google 的 Logan Kilpatrick 回复「12 月 2 日我们迈出第一步」，被解读为 Gemini 订阅可能开放给第三方 harness；官方没有公告，范围、套餐、工具都没说（官方人员一句回复，未确认）：起因是开发者 Kun Chen 说 Neon 不错，Google 只差「允许 Gemini 订阅用在任何 harness 里」，Logan 回了这句，获得 6500 多个赞；有账号随后把它发成「Gemini 订阅进 Agent 的证明」，樊凯表示等订阅能用在 Hermes 上就会大量使用（Logan 回复、Kun Chen 原帖、樊凯）
    前提或争议：我查到 Google 没有对「第一步」具体指什么做说明，Antigravity 的常见问题仍写着禁止第三方工具使用订阅，所以「任何 harness」是发帖人的解读，不是 Google 的话
    为什么值得看：Cursor、Codex 之外的 harness 能否用订阅额度，直接影响工作台的模型成本；先别依赖私有代理，等官方条款
  3. Codex 把 WebSocket 请求体上限从 16MB 提到 128MB（Charlie Marsh 原帖称是 Codex 的改动，Tibo 回复附和；未见官方更新日志）：原帖说大请求不再退回 HTTP，超限时的处理也快了约 5 倍；Tibo 回复「Actual engineering going on here」，steipete 转推（Charlie Marsh 原帖、Tibo 回复）
    前提或争议：只是发帖人自述，本期没看到对应版本号，生效范围（CLI、云端还是 App）没说
    为什么值得看：长会话、大附件的 Codex 任务遇到「请求过大」时，可以先查是不是旧版本的 16MB 限制
  4. GPT-6.2 Sol/Astra 的真实体验出现分歧：两位中文开发者自测认为复杂写代码和长任务不如 Opus 5.5，官方则在推 Pro 200 上 Sol 的 Ultrafast（个人自测与官方宣传并存，没有统一评测）：宝玉重度测试后称简单任务还行，复杂写代码任务比 Opus 5.5 差不少，结果还要 Opus 5.5 收尾；vikingmute 同意 Theo 的文章《Why I hate GPT-6.2 Astra》，称长任务能力差，6.2 变成莫名其妙打断任务，开 goal 也没用，并说这不是 6.2 独有；OpenAIDevs 则介绍 ChatGPT Pro 200 可以用 Ultrafast 搭配 Sol（宝玉自测、vikingmute、OpenAIDevs）
    前提或争议：各人任务不同，没有共同评测集；本期读到的帖子里没有 OpenAI 对这些具体反馈的回应
    为什么值得看：模型换代后，工作台不该只看发布页，应在自己的任务集上回归一遍再切默认模型
  5. Anthropic 官方博客称 Claude Code 团队 6–9 月合并的 PR 翻倍、需回滚的比例降超 40%（官方自报，博客发于 10/15；中文账号 11/20 重新整理成文）：做法是分层而不是单道关卡：先让 Claude 跑测试或截图自证，再由新上下文的子 Agent 审 diff；每个 PR 先过 Claude 审查，多个 Agent 找 bug 后再投票，够票才发出；之后还有阻断式安全审查、CI、按风险定的人工审批、合并队列和分阶段发布加快速回滚（meng shao 整理、Anthropic 博客）
    前提或争议：数字都是 Anthropic 自己的，回滚是占比不是数量，且同期合并量翻了一倍；这套零人工审批路径只用在 Anthropic 自己的低风险改动上，对外的 Code Review 产品只给发现、不替人批准
    为什么值得看：「先自证、再 AI 审并投票、按风险决定人工审批」可以直接抄进工作台的审查流程
  6. Google 论文 GUARD 让会改自己 harness 的 Agent 在保留每次改动前先查它弄坏了什么（二手转述，我没读论文原文）：akshay_pachaar 转述：自改 harness 的常见问题是改好一个任务却悄悄弄坏另一个，GUARD 每轮先把任务拆成是非自检清单，按清单给运行轨迹打分，固定住已通过的规则、把新坏的检查排在前面，并在同样任务上试多个候选改动，只有收益大于损失才保留，被拒的改动写进日志避免重试；测试时关闭这些，只跑一个冻结的 harness（akshay_pachaar 转述）
    前提或争议：「其他自改方法会掉到不如原始 Agent 之下」是转述里论文的说法，本期没看到论文数据，也没有独立复现
    为什么值得看：和「改动前先回归、拒绝的改动留记录」的做法一致，可对照工作台的自改机制
  7. Anthropic（ANT）上市次日盘前跌向发行价 $83：转帖称周五盘前约 $87–$89.67，较周四收盘 $97.17 低约 8%–10%（媒体与转帖转述，非交易所数据）：TestingCatalog 日报称首日收盘 $97.17、较 $83 发行价高 17%，盘后又跌超 3%，另引 FT 称 Anthropic 在美国企业使用上已超过 OpenAI；Gary Marcus 转引的帖子称盘前 $89.67、较周四收盘跌 7.7%、较盘中高点跌 22%，距发行价约 7%；op7418 转引的另一帖称盘前跌 10%、较上市后高点跌 25%；Gary Marcus 另引一条帖子批评定价从 $70–78 抬到 $83 还增发股份「对散户不体面」，这是引文作者与他的评价（TestingCatalog 日报、Gary Marcus 转引、op7418 转引、Gary Marcus 引批评）
    前提或争议：盘前价格波动大，各帖是不同时点的快照，数字不一致；「不体面」是评价，不是已证实的定价问题
    为什么值得看：上市后的价格会影响 Anthropic 的融资与定价节奏，供应商风险判断要看后续真实走势
