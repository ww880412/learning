X 简报 · 11/17（周二）

今日主线
  1. Simon Willison 与 Prime Radiant 发布 external sandbox：Claude Code、Codex、Pi 留在本机，命令在 WASM、Apple Container 或 QEMU 的 Linux 沙箱里执行（作者与实验室博文，原型尚未按敏感负载做安全审计）：Simon 今天介绍这套「外部沙箱」模式，并与 Superpowers 背后的实验室 Prime Radiant 一起放出三个实现同一协议的原型，演示给 Claude Code、Codex 和 Pi 用（原帖、仓库说明帖、代理与凭据、实验室博文、协议与接入仓库）。默认没有外网；加上允许名单代理后，只能访问指定主机，并用凭据替换代发带密钥的请求，agent 看不到真实密钥。Pi 可用 --no-builtin-tools 接上沙箱，连不上时会报错，不会退回本机执行
    前提或争议：官方博文写明这些仍是实验原型，还没有审计到能放心处理敏感负载的程度。可写挂载的目录仍可能被改坏，需要版本管理；沙箱里是 Linux，项目里面向 macOS 的 node_modules 或 .venv 往往要在沙箱里重装。仓库还提醒，Claude Code 靠 shell 前缀把命令转进去，它自带的 Read / Edit 不会被这条前缀转走
    为什么值得看：这是可直接抄进工作台的隔离做法——人还在本机用熟悉的 agent，执行和出网被限制在允许的目录与主机；不必把安全完全押在「每一步点批准」上
  2. Google DeepMind 的 Philipp Schmid 在 AI Engineer CODE 2026 讲《I deleted 90% of my harness (And It Got Better)》：约 350 项编程、终端和办公任务上，四种运行框架得分落在约 6 分以内，但 token 和费用差很多；他声明每个任务只跑了一次，小分差可能是噪声（官方演讲整理）：meng shao 对照官方文字稿做了介绍（原帖、官方演讲页、他的相关博文）。他的做法是把编辑、计划和任务列表等专用工具大幅删掉，主要留给模型一个 shell（看图还另加了媒体工具）。演讲整理写明：只给 shell 并不是每一列都最优，带看图的变体在这次实验里 token 更少、缓存命中更高。更强的模型会在一轮里写成脚本、把多处修改合并；较弱的模型即使用 shell，仍可能一步一调用。他的建议是做评测实验，不是直接改成生产环境的权限策略；口号是给模型一台计算机，而不是一盒工具，新模型发布后再把旧框架拆一次
    前提或争议：数字来自他在台上展示的单次实验，官方整理也写了不能据此给准确率做可靠排名。删掉工具并不自动等于更省钱，要看这个模型在这项工作上走的路径
    为什么值得看：工作台不该把旧的细粒度工具和提示词当成永远有效的补偿；换模型时应用同一批任务把框架再测一遍，统计的是完成任务花掉的 token，而不只是对错

    为什么值得看：这是他日常在用的 Codex 近期最烦人的容量错误之一；若属实会马上改善可用性，但还不能当成已经全线修复

话题 · No AI Slop 与「含糊会变成 slop」

4 条
  • yibie（@yibie）：补了昨晚 Lauren Tan 演讲里可操作的新细节。她画了一个倒金字塔：底层是 API、架构、lint、类型和测试，上面叠运行时和形式化验证，最顶上才是薄薄一层文字规则。她引用同行的数字，每天约 70% 的 token 花在验证上，并说和自己的情况吻合。顺序上不要先建软件工厂：内循环还在产出 slop，自动化只会放大。她们现在发版时会让 Grokbot 自动 fuzz、为 bug 开修复 PR 并自动合并，能这样做是因为大多数 PR 默认已经过关，走到这一步花了六个月。她还自报本人上个月合入约 3,000 个 PR。数字仍是台上单团队结果，没有第三方核实（原帖） 另见：X 海报 #1
  • meng shao（@shao__meng）：介绍 AI Engineer Code Summit 2026 演讲者和参会者共同撰写的 No AI Slop 宣言。五组对照是：结果重于产量，理解重于速度，自己的思考重于模型的第一稿，更好的工作重于更省事的工作，改进系统重于修补输出。slop 的定义是：你投入的心思，少于你要求接收者花在理解上的精力；用了 AI 并不自动等于 slop。他当时看到 GitHub Gist 上约有 504 个签名（原帖）
  • Matt Pocock（@mattpocockuk）：认为这场演讲里最有新意的一句是 “nuance tends to lead to slop”。要提高质量，就要设计 API 和自动检查，把 agent 决策里的含糊去掉，例如禁 useEffect、禁掉约 99% 的解释性注释（原帖）
  • 还没确认：约 70% token 用于验证，是她引用同行的数字并表示自己情况相近，不是独立统计；11,000 个 PR、0.5% 回滚和她本人 3,000 个 PR，仍是演讲自报。宣言签名数以 meng shao 当时看到的 Gist 为准，之后可能变化。禁 useEffect 仍是 Grok Bot 桌面框架 Dune 的局部选择，不是这条 API 普遍不该用
