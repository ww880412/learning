今日主线
  1. Postman 桌面版被曝自动给 Codex、Claude Code、Cursor 装插件和启动 hook，安装器源码还会尝试替自己的 hook 记「已信任」（用户日志 + 源码佐证，Postman 已在 issue 回应但未撤回）：GitHub issue 作者贴出 Postman 12.33.4 日志 auto-existing-upgrade 记录「claude-code:installed, codex:installed」，并在 ~/.codex/config.toml 看到 Postman marketplace、插件和带 trusted_hash 的 hook 记录；hook 在会话开始时注入「凡是 API 工程任务先加载 postman:api-engineer skill」，还装了 Postman CLI 和远程 MCP。另一用户在 12.35.1 复现同样的自动安装（这次没看到 trusted_hash）；有人补充 Copilot 也被写入（vikingmute 原帖、GitHub issue #14370）
    前提或争议：只影响已登录、更新到相关版本的 Postman 桌面用户；报告明确写「不能证明数据外传」。Postman 员工在 issue 里称打包安装是为了省去手动配置、下载页和更新流程有提示、可在应用内卸载，承诺把 opt-in 做清楚并复查 hook 审批和启动注入，目前没看到正式公告或 CVE。issue 里还有人实测：Codex 的 hook 信任记录就是一份同账号进程能算出来的哈希，Claude Code 的 -p 模式下项目 settings 里的 hook 直接生效——这是评论者自测，未经厂商确认
    为什么值得看：你的工作台也会往用户的 Codex / Claude Code 里装插件和 hook。可抄两步：装任何东西前在宿主里弹一次明确同意，绝不替自己写信任记录；定期扫描 ~/.codex/config.toml、~/.claude/settings.json、~/.copilot/ 里不认识的 marketplace、hook 和 MCP
  2. Claude Code 后台子 Agent 更省额度：状态行每 30 秒更新一次，改由 Haiku 5.5 从短笔记生成，单次更新成本约降 99%（官方已发布）：ClaudeDevs 说以前每次刷新状态行都要重读子 Agent 的整段对话，现在只读简短笔记；Boris Cherny 转发（ClaudeDevs 原帖、Boris 转发）
    前提或争议：官方称的 99% 指状态行这一项，不是子 Agent 整体用量；对你周额度的实际影响要自己看用量面板，目前没看到第三方实测
    为什么值得看：上周周趋势的判断是「子 Agent 默认别拆」，主要顾虑就是额度。这个改动说明进度汇报本身是隐性大头。可抄：工作台给长任务做进度显示时，用便宜模型读结构化笔记，不要每次让主模型重读全部上下文
  3. OpenAI 宣布收购 Pierre：Codex App 里看文件树、看 diff 用的就是它的开源组件，团队将做面向 Agent 的 Git 工作流（官方公告，待监管审批）：官方博客写明 Pierre 的 Trees、Diffs 库已在 Codex 里用，另有 Code Storage（给应用存代码和 Git 历史的服务）和语法高亮 Highlights；目标是让 Codex 把公司发布的代码和人的决策连起来。开源项目继续开源，Code Storage 客户收购后可继续用，金额未披露（OpenAI 公告原帖、OpenAI 博客、Greg Brockman 原帖、宝玉 原帖）
    前提或争议：交割前两家仍独立运营；博客顺带提到 OpenAI 内部用自研源码后端 Pando 支撑工程师和 Agent 并行。同一天还有 Conductor 加入 Meta 等收购，见话题组
    为什么值得看：Codex 正从「写代码」往「审代码、管分支」延伸，和你工作台的 diff 审阅、分支管理会正面重叠。可抄：把 diff 浏览和行内修改做成一等界面，而不是只给 Agent 一条终端输出
  4. Claude Code / Cowork 原产品负责人 Cat Wu 宣布加入 OpenAI，负责 Core Products 产品管理（本人宣布，OpenAI 高管公开欢迎）：她说将和 Codex 负责人 Tibo（@thsottiaux）以及 PM 团队一起做「为你和团队兜底、让你保持掌控」的 Agent；Greg Brockman、Tibo 发帖欢迎。上期写过她离开 Anthropic 时未说去向，这次补全（Cat Wu 原帖、Tibo 原帖、Greg Brockman 原帖）
    前提或争议：本人宣布属实；具体负责 ChatGPT 还是 Codex 哪条线，帖子只写 Core Products，没说细
    为什么值得看：Claude Code 的产品思路（权限默认信任 Claude 自动批）会被带进 OpenAI。两家产品形态会更像，你工作台对两边的适配层可以按同一套「任务、权限、审阅」抽象来设计
  5. NVIDIA 论文《You don't need long context》：频繁压缩上下文几乎不掉分，Opus 4.5 每步只带一份状态摘要，SWE-bench Verified 70.2 对比全历史 70.0（论文作者自测）：论文比较全历史、到阈值再压缩、每动一步就压缩三种做法；压缩到 24K/18K 时 Opus 4.5 反而到 74.8，单步压缩把峰值上下文中位数从 32K 降到 8K；作者估算在开源模型上 256K 上下文的单 token 生成成本是 16K 的 3.6–7 倍（omarsar0 原帖、arXiv 论文）
    前提或争议：用的是极简 mini-swe-agent 一类 harness 和 Opus 4.5、GPT 5.6 Sol；GPT 5.6 Sol 单步压缩在 SWE-bench 上低 2 分。部分开源模型（Qwen 3 Coder Next）在最紧的 16K 设置下从 53.0% 崩到 3.6%。成本倍数是作者按 H100 吞吐换算的估计，不是厂商价格
    为什么值得看：直接可抄的是附录里的压缩模板：交接摘要只记目标、已确认事实（路径、命令、输出）、已改文件和验证状态、走不通的路、下一步与完成条件，而不是复述过程。长文档改成放进文件、让 Agent 用 grep 按需读
  6. Matt Pocock：对 Agent 来说「可读性」变成「可验证性」，判断一个模块好不好改，看测试和可执行性而不是读起来顺不顺（个人观点）：他认为人只在偶尔抽查重要 PR 时需要读懂代码，命名用不用和人描述需求时同一套领域词更重要；一个满是性能技巧但 100% 测试覆盖的模块，人要一两小时上手，Agent 跑测试摸一摸就能动。他同时在考虑把自己的 skills 发到 npm，让人按 Agent 动态加载、锁定版本（Matt 原帖、skills 上 npm）
    前提或争议：观点帖；他在回复里也说「单向门」类 PR 仍要人逐个审。skills 上 npm 目前只是想法
    为什么值得看：给工作台的代码评估和 skill 分发都有用。可抄：评估仓库「适不适合交给 Agent」时把测试覆盖、可快速执行的检查列为第一指标；技能包做版本号和锁定，别只有最新版
  7. OpenAI 称自动化漏洞流水线一次跑出 948 个 Linux 内核本地提权漏洞并配好补丁，API 成本约 120 万美元（官方称，用的是尚未发布的网络安全模型）：OpenAI 官方帖写「发现、利用、打补丁」全自动；研究员 Eric Wallace 补充一周内找到约 1000 个，以前人工一年大约 20 个，还发现至少 10 类新利用手法，并称会把大量前沿算力无偿用于开源项目修洞；Greg Brockman 折算约每个漏洞 1000 美元（OpenAI 原帖、Eric Wallace 原帖、Greg Brockman 原帖）
    前提或争议：数字都是 OpenAI 自报；补丁是否被内核维护者接收、这些漏洞是否已分配 CVE，帖子里没说。模型本身还没发布，The Information 报道新网络安全模型可能本周五和新 Sol、Astra 一起来（爆料未确认）
    为什么值得看：「Agent 找漏洞 + 自动出补丁」的成本已经到单个漏洞千美元级。企业工作台迟早要接入这类审查，可以先预留「安全扫描 → 生成补丁 → 人审合并」的流水线位置
  8. Kimi K3.1 Pro 开源权重：2.8T 总参数、每 token 激活 104B，原生 4-bit，仓库约 1.56TB（官方发布，许可证有营收门槛）：Moonshot 在 Hugging Face 放出权重；Thom Wolf 拆解：896 个专家每次选 16 个，多数层用线性注意力、每 4 层一层稀疏注意力撑 1M 上下文；模型卡上 BrowseComp 92.1、带工具 HLE 70.0、SWE Marathon 51.7 居首，纯推理和网络安全偏弱，且 Moonshot 多数编码评测是用 Claude Code harness 跑的（Kimi 原帖、Hugging Face 模型页、Thom Wolf 原帖、Nathan Lambert 原帖）
    前提或争议：跑分来自厂商模型卡；许可证是改过的 MIT，xeophon 和 Thom Wolf 都提到对做模型 API 服务、营收过线的公司有附加条件，细节要看许可证原文
    为什么值得看：开源权重第一次在 Agent 编码类评测上和 Opus 5.5、GPT-6 Astra 来回拉锯，而且评测直接用 Claude Code harness。工作台的「模型可换」层值得把它列进私有化部署候选
