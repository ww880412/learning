模型

今天模型圈只有一个主角：DeepSeek V4.1-Flash-1017，关注名单里十几个人都在发。官方跑分很猛，上手实测褒贬参半。

DeepSeek V4.1-Flash-1017 发布

  • TestingCatalog（@testingcatalog）：新的开放权重模型，DeepSWE 1.1 得 77%，超过 GLM-5.3、Kimi K3，也超过 GPT-5.6 Sol 和 Opus 5；网页、API 和 Hugging Face 都已上线，而且极便宜（原帖）
  • Thomas Wolf（@Thom_Wolf）：DeepSeek 管这叫「小更新」，Terminal-Bench 4.0 却从 31.2 涨到 42.3；他觉得最有意思的是完成更快、输出更短，少用 token 正是成本下降的实际途径；权重照例是 MIT 协议，他想看这些分数离开 DeepSeek 自家评测环境还站不站得住（原帖）
  • Nathan Lambert（@natolambert）：小版本号加日期的命名太离谱，但跑分跨度很大，可能比 GLM 5.3 更强还自带视觉，「开放权重之王回来了？」（原帖）
  • 宝玉（@dotey）：API 模型名不变，代码不用改；几项自动办事的测试超过 Opus 5，高难度问答和写完整程序仍落后，分数都是自测；同时开放 Search 和 Fetch 两个接口，每千次成功请求 5 元，接进 Claude Code、Codex 或 DeepSeek Harness 时自动发起的搜索 11 月 1 日前免费；模型 7630 亿参数，个人电脑跑不动（原帖）
  • meng shao（@shao__meng）：训练用了「带自我反馈的强化学习」，目标是整个任务的最终结果，而不是单轮对话；商业上最重要的一步是把内部搜索引擎开放成 API，抢 Agent 工具的入口（原帖）

上手实测：便宜好用，但还不是 Opus

  • 花叔（@AlchainHust）：拿 10 多个案例实测，用了 5 亿 token 只花 28 元，缓存命中率 99.41%；他认为除了订阅的 Claude Code 和 Codex，这可能是现在价格最低、效果最好的选择，审美和长程任务跟 Opus 5.5 还有差距（原帖）；做动效的水平基本仅次于 Claude（原帖）
  • WquGuru（@wquguru）：同一段「能抓、能拉、能扔的果冻小熊」提示词，静止时不输 Fable 5.1 加 Opus 5.5 的组合，一上手就露馅，一拉就撕成薄片，眼睛还会飘出脸外（原帖）；另一个任务它连续跑了 1 小时 47 分钟、调了 212 个命令，长程自主能力确实有突破（原帖）
  • LinearUncle（@LinearUncle）：26 分钟做出 3D 雷峰塔，3D 能力比以前进步很大（原帖）；软糖小熊看起来和 Opus 做的一样好（原帖）
  • 歸藏（@op7418）：用给 Opus 5.5 写的游戏特效提示词试了一下，细节和创造性差不少，但能用（原帖）
  • Orange AI（@oran_ge）：用 DeepSeek Harness 加新版 Flash 做视频，50 分钟做出一个垃圾（原帖）
  • 【观点】国内几家很久没发新模型：字节、MiniMax、月之暗面都已近 4 个月或更久没发新模型，百度 ERNIE 5.1 快半年了——meng shao @shao__meng（原帖）
  • 【发布】OpenMoss 开源绘画模型 MOSS：5.6B 参数，中文字写得不错，但推理能力弱，写中文时要把文字内容写明确——Gorden Sun @Gorden_Sun（原帖）

💡 一句话：跑分说它超过 Opus 5，实测说它做不出 Opus 5.5 的细节；最划算的用法大概是让强模型拿主意，它来干量大的活。

Agent 与编程

今天的话题是代码多到人读不过来以后怎么审：Anthropic 公开了 Claude Code 团队的做法，大家在拆细节，也在争人工审批还有没有用。

Claude Code 团队怎么审 AI 写的代码

  • meng shao（@shao__meng）：没有取消审查，而是把「人读代码」大多交给机器；一次改动要过七层：提 PR 前 Claude 先自证、AI 审查、安全审查、自动检查、按风险决定几个人批、合并队列加功能开关和灰度、快速回滚；AI 审 AI 曾一夜来回 50 多轮，加了三轮封顶等规则后，一轮通过率从 65% 升到 78%（原帖）
  • 宝玉（@dotey）：做了中英文讲解视频，用「一摞带洞的奶酪片」打比方：每道检查都会漏，叠起来就很难漏，底下还有一张网兜底；他引用的官方帖说，Code Review 已对 Claude Team 和 Enterprise 套餐正式开放（原帖）
  • Viking（@vikingmute）：最受用的是审查要能收敛，这正好解答了多 Agent 审查会互相折腾的问题；他怀疑最高风险要两人批准是否真有用，人看得过来吗（原帖）
  • Gorden Sun（@Gorden_Sun）：代码都由 AI 写了以后，人负责判断该不该做、把关计费和自动更新这类高危代码、定下别人会效仿的架构、看证据而不是看代码（原帖）
  • elvis（@omarsar0）：在编码 Agent 的时代 PR 这种形式很糟，应该让 Agent 按需生成适合每个人的视图和材料（原帖）
  • 【观点】让最短路径就是正确路径：转述 Grok Bot 团队 @poteto 的「倒金字塔」：精力优先花在改代码库（架构、类型、模块边界），其次是 lint、测试和 CI，规则文件和人工审查放最后——meng shao @shao__meng（原帖）
  • 【观点】软件工程「全自动化」的真实样子：工程师比 2025 年更多，需求还在涨，大家从没这么累过，而代码几乎全由 Agent 写——François Chollet @fchollet（原帖）
  • 【观点】Rust 拖慢 Agent：大项目编译太慢，Agent 拿到反馈慢，资源消耗又大，所以他只在核心组件用 Rust，其余回到 Electron——宝玉 @dotey（原帖）
  • 【发布】tsc-ts：Vercel Labs 把 TypeScript 编译器移植回 TypeScript，用 scriptc 编译后比 Go 写的 tsgo 快 2–4 倍——Guillermo Rauch @rauchg（原帖）
  • 【发布】JetBrains 开源 Pi 桌面端 ThinkRail：底座是 pi-coding-agent，模型、技能和会话仍由 Pi 管，每个工作区对应一个 git worktree——小墨同学 @xiaomovps（原帖）
  • 【技巧】自建 Magpie 网关：在海外 VPS 上部署 @yetone 的 Magpie，相当于有了自己的 OpenRouter，能用 Codex 里的额度，装插件后还能用 TRAE、WorkBuddy 送的免费模型——向阳乔木 @vista8（原帖）

安全与政策

OpenCode 泄露是今天最大的安全事件；Anthropic 的立法立场和中国新的 AI 技术出口目录也值得留意。

OpenCode 因「蒸馏攻击」泄露密钥

  • 宝玉（@dotey）：OpenCode 说前一晚的事件影响 1.4% 的 Console 用户，都是绑定了外部服务商的，没收到邮件就没受影响；据媒体转述，邮件提醒工作区里存的 OpenAI、Anthropic 等密钥可能已泄露，要作废换新并查最近用量（原帖）
  • TestingCatalog（@testingcatalog）：部分用户的 OpenAI、Anthropic、Google 余额被刷光；如果这是最省事的蒸馏途径，说明大厂自己防得更严了，用小服务商反而更不安全，大厂的 token 也更值钱了（原帖）
  • Nathan Lambert（@natolambert）：把盗 API 密钥的网络攻击也归进「蒸馏」很奇怪，不清楚量为什么这么大、和训练模型有什么关系（原帖）；他还问 Kimi 为什么直接把 Claude 的 token 提供给用户，这不算蒸馏，但做法可疑（原帖）
  • sarah guo（@saranormous）：这已经是过去一周的第三家公司了（原帖）
  • 【观点】Gary Marcus 炮轰 Anthropic 的立法提案：他认为提案违背了 Anthropic 过去的所有说法，让它即使出了造成 5 亿美元损失或几十人死亡的事故也能大幅免责——Gary Marcus @GaryMarcus（原帖）
  • 【消息】中国拟限制 23 项 AI 技术出口：商务部、科技部拟把大模型、智能体、算力集群等列入限制出口目录，已公开的开源技术豁免，「先开源、后出口」成了合规路径——meng shao @shao__meng（原帖）
