X 简报 · 10/28（周三）

今日主线
  1. Claude 新模型默认不返回思考摘要：Ethan Mollick 说 Claude 和 ChatGPT 不再给详细的思考摘要，人想在 AI 干活途中插话变难了，这会把人推向「全自动」而不是「人机协作」（原帖、原帖、Claude 思考文档）
    前提或争议：Claude 这边官方文档可查：Opus 5.5、Sonnet 5.5、Fable 5.1 等模型的 display 默认是 omitted，思考块为空，要显式设 display: "summarized" 才拿得到摘要，原始思维链任何设置都不返回。Mollick 说原因是防蒸馏加体验，这是他的推测；ChatGPT 一侧目前没看到对应公告
    为什么值得看：工作台调 Claude API 时要显式打开 summarized（或 beta 的 updates 进度文本），否则审阅界面里看不到任何思考过程；Claude Code 里也有用户报告摘要被服务端实验去掉（issue #75607，用户自报）
  2. Cursor 设计模式能直接在页面上批注：Cursor 官方发布 design mode 新功能 Annotate：改元素、在页面上画、按不同屏幕尺寸审设计，作为给 Agent 的视觉提示（Cursor 原帖、TestingCatalog 原帖）
    前提或争议：官方已发布，只在 design mode（对运行中的应用）里用；宝玉说印象中 Cursor 早就有类似标注功能（原帖）
    为什么值得看：前端任务里「圈出来 + 写一句」比长段文字描述准；工作台审 Agent 做的界面时，可以抄这种「批注就是指令」的交互
  3. Anthropic 建议把子 Agent 并回主循环：Claude 官方文章称，在几家企业部署的对比里，「单 Agent + skills + 工具检索」常比拆子 Agent 质量更好、成本和延迟更低，一家客户换成单循环后运行快约 2 倍；Addy Osmani 转发时给的规则是：只有并行、需要全新上下文、或一个 Agent 真选不对工具时才留子 Agent（Addy Osmani 原帖、Claude 文章）
    前提或争议：官方称，是 Anthropic 自己在客户项目里的对比，没公开数据；文章也说子 Agent 在验证、并行、权限隔离上仍有用，系统提示里工具定义超过 30–50 个时选工具会变差
    为什么值得看：能抄的一步：先建一套 10 条黄金样例的端到端评测，一次只把一个子 Agent 改成 skill + MCP 工具，对比哪些任务翻了（不只看总分），每个任务跑不止一次，赢的留下
  4. MiniMax 开源自托管的 Agents API：meng shao 介绍 MiniMax 开源的 OpenAgentCore：官方 OpenAI SDK 只改 OPENAI_BASE_URL 就能用，每个 Session 可选 Codex、Claude Code 或 MiniMax Code 当 harness，模型和沙箱（microsandbox、E2B、Docker、本机）都按协议可换（原帖、OpenAgentCore 仓库）
    前提或争议：转述仓库 README，我只确认了仓库存在，没跑过；目前没看到第三方实测
    为什么值得看：它的分层（Core 调度和持久化、沙箱节点、工作区存储和算力分开、harness 适配器、模型协议）几乎就是工作台的骨架；「算力空闲就释放、工作区文件留着换节点恢复」这条可以直接对照
  5. DeepSeek Harness 插件生态起来了：歸藏说 DSH 插件生态正在快速发展，不少爱折腾的年轻人只用 DSH，排前五的插件有 dsh-market、DSH-better-sidebar、dsh-context 等；向阳乔木说 Obsidian 插件能很轻松移植过去，自己开源了几个（歸藏 原帖、原帖、向阳乔木 原帖）
    前提或争议：小墨同学说他读了升级日志并上手试过：0.2.1 系列让 Agent 能自己写插件，支持第三方插件源、依赖管理和热重载，还有实验性的 Claude Code Mods 兼容层，但两套插件还没完全打通；GitHub 最新是 0.2.1-rc.3 预发布（原帖）。歸藏也提到 dsh-bili-scroll 插件让 DeepSeek 去刷 B 站，他的视频评论区已出现 DeepSeek 在聊天（原帖）
    为什么值得看：「Agent 自己写插件 + 热重载 + 兼容别家插件格式」是 DSH 拉起生态的三步，正是客户端插件生态可以参考的路线；B 站的例子提醒，插件能替用户上网发言，就得先有权限边界
  6. 又一篇论文：Agent 记忆层常输给直接检索原文：elvis 转述论文《Memory Tax》：在 LongMemEval、PersonaMem、MINT-Eval 上，很多专门的记忆系统得分低于「对原始对话做朴素 RAG」，成本还更高（elvis 原帖、论文）
    前提或争议：elvis 的解读；论文把记忆系统的价值拆成「记忆收益」（RAG 答不出、记忆答出）和「记忆税」（RAG 答对、记忆答错），原因是建记忆时会改写历史，有的事实被丢掉或扭曲；换骨干模型时记忆系统波动也比 RAG 大。基准都是对话记忆类，换到代码库或工单场景结论未必一样
    为什么值得看：论文给的补救很简单：查记忆的同时也查原文，两路一起重排，能减少「记忆税」。做记忆系统时先留原文和这条回退路径，再上抽取和摘要
  7. Manus 的 AI Native 改造：一个人带一个全栈 Agent：Manus 联创张涛发文讲内部改造，宝玉和 meng shao 都做了解读：统一入口 Mono 加一份给 AI 看的说明书，本地能跑完整 Manus，验证从 5–10 分钟变成几秒；工程师一人同时开十几二十个 Session；人均每月 Token 约 1 万美元；移动端 7 人维护 4 个 App（宝玉 原帖、meng shao 原帖、原文）
    前提或争议：都是 Manus 自己的说法，数字没有外部核实；上线审批仍留在人手上
    为什么值得看：能抄的几步：先做一个让 Agent 看到全局的统一入口和说明书；让 Agent 在本地端到端验证；用测试账号录屏当证据，代替逐行看代码；把发版这类流程写进 AGENTS.md，谁都能让 AI 来做
  8. OpenAI 和 Anthropic 都称模型推翻了「指数时间假设」：Deedy 说两家的模型 10 月 16 日各自解出 3-SAT，得到同样的 2^(n/√log n) 上界，不等于 P=NP，但比此前认为的可能更快；Anthropic 放在 GitHub 的论文署名只有 Claude，论文称核心算法由内部研究版 Claude 用 1400 万输出 Token、无人类输入找到（Deedy 原帖、原帖、宝玉 原帖、OpenAI 论文、Anthropic 论文）
    前提或争议：两篇都是预印本，没经过同行评审；Gary Marcus 收回了自己「意义重大」的说法，说这个结果需要背景（原帖）
    为什么值得看：同一个难题被两家模型独立做出、能互相印证，是模型做原创研究的一类新证据；核查结果出来前别当定论引用。多方说法见下面「话题 · AI 做数学」

Agent 与编程

8 条
  • 【观点】Anthropic 平台工程负责人 Katelyn Lesse 列出上千个 Agent 一起跑时的四个难题：调度、身份与授权（授权基本还是空白）、一个 Agent 被提示注入后可能经共享记忆传给全队、要有改不了的操作记录和一键总闸——宝玉 @dotey（原帖、原文） 另见：X 海报 #1
  • 【观点】Viking 推荐 AmpCode 的 Thorsten Ball 写的《How I work with Agents》，摘了几条：用最新最强的模型、告诉 Agent 要什么而不是怎么做、让 Agent 看见整个流程（E2E、生产日志、部署）、要证据（E2E、对比数据、截屏），并把它写进 AGENTS.md 当验收条件——Viking @vikingmute（原帖、Thorsten 原帖）
  • 【观点】Matt Pocock 访谈：他试了几个月 Spec 驱动开发，代码反而越来越差，结论是代码本身就是 Agent 的工作环境；他认为多数人 effort 开得太高，自己用 medium——meng shao @shao__meng（原帖、访谈视频）
  • 【发布】skill-diet 是一个管其他 skill 的 meta-skill：压薄 SKILL.md、校对工具说明是否过时，瘦身版只有在「旧 / 新 / 无 skill」同任务评测里不输才保留；作者自测在真实 skill 上能砍 70%–80% token，还测出了文档里已经失效的命令——meng shao @shao__meng（原帖、skill-diet 仓库）
  • 【发布】Uncle Bob 开源 ub-mode，把 Clean Code 和 TDD 拆成「先跑通、再做对、再养成习惯」三段给 coding agent，用 CRAP 小于 10、重复度、变异测试这些机器能量的门槛——meng shao @shao__meng（原帖、ub-mode 仓库）
  • 【观点】Harrison Chase 从 Hex 4.0 总结三条通用做法：让 Agent 用代码生成定制界面、界面围绕「审阅 Agent 的工作」来设计、核心基础设施要扛得住 Agent 带来的用量——Harrison Chase @hwchase17（原帖）
  • 【观点】Thariq 认为开源软件需要一种新的分发方式：用户用 Agent 改自己的副本，上游更新还能自动合进来；coding agent 能做到，但不会自动去做——Thariq @trq212（原帖）
  • 【发布】Replit 推出 Cloud Agents，能跑任意仓库，把自然语言需求变成测试过的 PR，最后由工程师审批；官方称自家设计团队 6 个月用它上线了 25 万多行代码——Amjad Masad @amasad（原帖、Replit 原帖）
