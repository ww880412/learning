模型

DeepSeek 一天里既放出了推理框架，又被几方实测出 V4.1 Flash 1017 的长进；海外则是扩散语言模型 Mercury 3 和几款专用模型。

DeepSeek 开源推理框架 DeepInfer

  • 宝玉（@dotey）：DeepInfer 是 DeepSeek 自家线上服务用的推理框架，连同配套的 deepseek-recipe 一起开源，Apache 2.0 可商用；目前只支持 V4.1-Flash，要 Blackwell 或昇腾 950 这类数据中心显卡（原帖）
  • meng shao（@shao__meng）：这是 DeepSeek 线上真实服务同源技术栈第一次对外公开，基于 vLLM 构建，借鉴了 SGLang 和 TensorRT-LLM；此前开源的 FlashMLA、DeepGEMM、DeepEP 等「零件」终于有了整机（原帖）
  • swyx（@swyx）：知乎上写得比推特多得多：单集群日吞吐 155 万亿 token，按闲时价每卡每小时收入 38 美元；GPU 成本大约 5 到 10 美元一小时，等于 DeepSeek 在自己这么低的价格上还有约 80% 的毛利（原帖）
  • Thomas Wolf（@Thom_Wolf）：DeepSeek 的开源连击有点离谱了：FlashMLA、DeepEP、DeepGEMM、3FS 文件系统，今天又是 V4.1-Flash 背后的完整推理引擎（原帖）
  • Orange AI（@oran_ge）：把低价的秘密武器全开源，会推着所有模型一起降价（原帖）；有人算过，用这套框架回本周期从 10 个月缩到 4 个月（原帖）
  • Nathan Lambert（@natolambert）：这种拉动模型采用的方式很野，对社区很好；时机也很巧，美国政府刚禁止联邦机构使用 DeepSeek（原帖）

DeepSeek V4.1 Flash 1017 实测

  • karminski-牙医（@karminski3）：后端 Agentic Coding 能力从 Grok-4.6 的水平跃升到国产旗舰水平，让人怀疑 v4.1-pro 还有没有必要；但性格从「主动」变「保守」，得配好 harness，控制预算的能力也变差了（原帖）
  • Gorden Sun（@Gorden_Sun）：Vals AI 测出它在多步骤进攻性网络安全任务上打赢了 GPT 6 Sol，而 Sol 还是开了 Daybreak 可信访问的（原帖）
  • 向阳乔木（@vista8）：Agent Arena 榜单开源模型第 1、总榜第 11（原帖）
  • Orange AI（@oran_ge）：用它做视频动效测试，12 分钟、约 0.2 美元，便宜但效果和 Opus 5.5 有差距，它给自己打 7.5 分（以 Opus 为 10 分）（原帖）
  • WquGuru（@wquguru）：自己 95% 用 Claude Code、5% 用 DeepSeek Harness，Claude 不愿干或有风险的活（逆向、配代理）都丢给后者，1017 版之后已经基本顶得上（原帖）
  • 【发布】Inception 发布扩散语言模型 Mercury 3：同价同分下比 Luna、Haiku 快 4 到 8 倍，OpenRouter 实际数据是快 2 到 4 倍、有效价格便宜 2 到 4 倍——Deedy @deedydas（原帖）
  • 【发布】Mistral 发布 Voxtral 3 语音模型：语音转文字和文字转语音一起出，Voxtral Small Transcribe 3 在 Artificial Analysis 语音转写榜排第 3——TestingCatalog @testingcatalog（原帖）

  • 【发布】Coco Labs 推出首个设计专用模型 Vyb：从品牌官网生成分层可编辑的营销图，145 种字体测试中 95.3% 匹配字形——TestingCatalog @testingcatalog（原帖）

Agent 与编程

今天的关键词是 harness 和评测：几位做工具的人公开反驳「harness 已死」，评测圈在推用决策模型当 LLM 裁判；Meta 和 Addy Osmani 各有一篇实战长文。

「harness 已死」？没有

  • elvis（@omarsar0）：和「提示词工程已死」「RAG 已死」一样，是蹭流量的误读，源头是几篇实验设计很差的论文（原帖）
  • Harrison Chase（@hwchase17）：建议顺序是先用现成 harness（如 deepagents），再加上下文（skills、工具），必要时再微调 harness，最后才上 LangGraph 写工作流（原帖）；托管版 deep agents 补的是多人调用同一个 Agent 时每个人自己的凭据和记忆（原帖）
  • Guillermo Rauch（@rauchg）：Vercel 把驱动 eve 和 Workflows 的持久化能力开放给所有 harness，比如 Pi 和 OpenCode，本地、Vercel 或自建都行；Claude Code 和 Codex 也能这样变得可持久、可观测，只是它们不是为嵌入设计的（原帖）

用决策模型做评测

  • Hamel Husain（@HamelHusain）：新文讲怎么为评测任务选决策模型、怎么调阈值（别默认 0.5）、怎么读分数，带不少交互图（原帖）
  • elvis（@omarsar0）：推荐这篇；他们内部评测里，Jev 这类「System One」模型很适合当 LLM 裁判（原帖）
  • Harrison Chase（@hwchase17）：线上流量里的裁判，价值在于被它标出来的输出：先用人工标注校准，标出低分、确认真失败、补进评测、修复再跑，线上能找到离线数据集里从没有过的失败（原帖）
  • 【技巧】Meta 的「瘦编排器」Agent 架构：单个全能 Agent 在生产里知识互相串味；改成约 1300 行确定性代码的编排器只做路由，下面 14 个上下文隔离的专业 Agent，新能力只加流程模板不加 Agent——meng shao @shao__meng（原帖）
  • 【观点】Addy Osmani：瓶颈从写代码变成验证代码：测试成了 Agent 判断自己是否完成的传感器，首选 E2E，再加属性测试和差分测试；慢或不稳定的测试会把 Agent「训练」成只会重试——meng shao @shao__meng（原帖）
  • 【发布】OpenAI API 支持 12 小时提示缓存：可以给共享指令选 12 小时、新对话内容保持 30 分钟，整天复用同一段上下文的常驻 Agent 能省不少——OpenAI Developers @OpenAIDevs（原帖）
  • 【发布】trim-1：1.2 MB 的上下文裁剪模型：只删 Agent 用不上的行、不改写原文，712 棵梯度提升树，单核毫秒级，不要 GPU——yibie @yibie（原帖）
  • 【技巧】给 Claude Code、Codex、Cursor 共用一份会自我改进的记忆：一个工具里的纠正和技能能跟到另一个工具——Akshay 🚀 @akshay_pachaar（原帖）
  • 【消息】Claude Code Desktop 新开任务可以选模型了：不用再担心每个新任务都默认开昂贵的 Fable——宝玉 @dotey（原帖）
