X 简报 · 11/13（周五）

今日主线
  1. Anthropic 推出 Claude Meetings（官方发布）：Claude 可以作为一个可见参与者加入团队视频会议，边开会边写文档、白板和其他成品，会后纪要、待办和它做的东西都留在会议页；目前在 Team 和 Enterprise 套餐以测试版推送，先支持 Google Meet：官方帖北京时间 11/13 凌晨发出（Claude 原帖、补充、会后页、介绍页）；会上可以口头或在聊天里提问，默认书面回答，调用已连接的工具前要经过当事人许可；Team 套餐默认可用、管理员可关掉，Enterprise 要管理员为全部或部分组织打开（原帖）
    前提或争议：测试版不向部分组织开放，包括零数据保留（ZDR）、HIPAA 就绪配置和客户管理加密密钥（CMEK）；默认不加入有组织外客人的会议，外人中途进来它会退出，管理员可以改；测试期间纪要和转写免费，会上回答若调用了已连接的工具会计入套餐用量，文档和白板等成品免费用到 2027 年 2 月 10 日；它保存转写、摘要和屏幕描述，不保存音频
    为什么值得看：这是你在用的 Claude，也正好对上昨天 Grok Bot 1.0 的会议能力；可对照「Agent 进会之后谁能看见、外部客人怎么处理、会中写文档要不要审批」这几条，抄进工作台的会议协作设计。Anthropic 开发者关系 Alex Albert 称，现在要从 Claude 拿到好结果，关键是找出它还缺哪一段上下文并补上，Claude Meetings 就是把会里剩下的那几片带进去，他们内部已经觉得有用（原帖）
  2. Codex 与 ChatGPT 负责人 Tibo 称「可积存的重置」（banked reset）已经激活，很快会发到大家的账户里（官方人员宣布）：北京时间 11/13 清晨发出（原帖）；宝玉把它理解成送了一张重置卡（原帖）。同一条里他还提到 ChatGPT 的 dot 今日更新：官方称回复更快、少套话、更能跟进，并开始听从自定义指令，可在对话里交代怎么说话、哪些动作要先经你同意，也可在移动端 Customize > Behavior 或网页、桌面的菜单里设置（ChatGPT 官方帖）
    前提或争议：Tibo 没有写重置覆盖哪些产品、额度口径和到账的具体时间，只说 sometime soon；他同时宣布了 dot 更新，不要把这两件事混成一件。昨天他只暗示「也许该发一张可存着用的重置卡」，今天是说已经激活，目前还没看到产品内的说明页
    为什么值得看：你在用 Codex 和相关额度，这张重置什么时候到、能用在哪，会直接影响这几天的用量安排
  3. 谷歌发布 Gemini 4 Hydrogen（官方发布）：定位日常编程和 Agent 工作流的快模型，官方称 100 万 token 上下文内统一计价为每百万输入 1.50 美元、输出 7.50 美元；对标 Gemini 3.8 Flash 时，默认高思考档完成任务快 2.5 倍、编造减少 5 倍以上，并在 Google Antigravity 推出可在同一会话里切换 Carbon 和 Hydrogen 的 Orchestrator：Logan（原帖、补充、速度对比）；Demis 称适合日常编程和 agentic 工作（原帖）；官方博客
    前提或争议：速度、跑分和「编造减少 5 倍」都是厂商口径；博客还称 Terminal-Bench 4.1 为 57%，对比 3.8 Flash 的 18.2%；Orchestrator 在 Terminal-Bench 4.0 上接近 Carbon 的成功率，平均少用 24% 额度、快 19%。它已向 AI Studio、Gemini API、Gemini 商务版、Gemini 应用、Search 以及付费 Pro / Ultra 的 Antigravity 开放，免费用户在 Gemini 应用里由自动选模型接入。Simon Willison 根据公开定价整理：Carbon 和 Argon 目前同为每百万输入 2 美元、输出 10 美元，并将于 12 月 1 日起涨到 4 / 20 美元；Hydrogen 为 1.50 / 7.50，现在只比前两者便宜约 25%，涨价后价差会到约 75%，仍明显高于 Claude Haiku 5.5 和 GPT-6 Luna 的 0.10 / 0.50；他还测了 Hydrogen 画鹈鹕，认为在价格接近的情况下质量明显更差（整理帖、他的说明）
    为什么值得看：这是可以进工作台多模型调度的执行层模型；价格，以及「同一会话里 Carbon 做判断、Hydrogen 做执行」的 Orchestrator，都是可对照的做法
  4. Matt Pocock 写出他用了几个月的 Home Repo 做法：单独一个仓库放共享的 skill、AGENTS.md 和文档，Agent 从这里启动，用导航指针指向其他仓库，需要时再打开或克隆（作者自用后公开）：（原帖、文章和可复制的提示词、文章帖）；团队可以共用同一个 Home Repo，子仓库只留本仓库自己的规则；大约 20 个仓库时指针可以直接写在 AGENTS.md 里，到大约 400 个就要按业务域拆文件
    前提或争议：这是他的工作方法，不是某个官方产品功能；他在回复里补充，并行开发时在子仓库里用 git worktree，而不是做在 Home Repo 里（原帖）
    为什么值得看：这正是可以抄进工作台的一步：共享 skill 和规则只保留一份正本，各仓库用指针引用，避免每处复制一份然后慢慢漂掉
  5. OpenAI 发布两款网络安全产品 Daybreak Defense Factory 和 Daybreak Red Team（官方发布）：前者让 Agent 调查漏洞并准备补丁供工程师审查，可与 Codex 一起改补丁；后者用一组 Agent 测 Web 应用、核实漏洞并验证补丁是否挡住利用：Greg（原帖）、Tibo 提供演讲录像（原帖）；Defense Factory、Red Team、Cyber at the Frontier
    前提或争议：官方称补丁要工程师审查和测试后才合并；Red Team 用隔离环境和 Guardian 审查，控制 Agent 能碰到的应用和端点。目前是产品发布和申请使用，还没看到第三方实测
    为什么值得看：把「找洞、写补丁、再验证补丁」交给 Agent，但合并权留在人手里，这和给 coding agent 开写权限时的审批边界是同一类设计

    前提或争议：辞职已是公司正式公告，不再是昨天还在传的「董事会可能罢免」。对 CUDA、开源模型（Nemotron）和客户供货的实际影响，官方没有另作说明，各方看法见下面话题组
    为什么值得看：英伟达是整个行业算力的中枢，换帅会改变模型公司的芯片供应和开源权重预期，需要把「已确认的人事」和「尚未发生的业务变化」分开看
  7. 小墨同学整理了 5 个用于监控和节省 Grok Bot 额度的机器人（作者自用经验）：他已从 100 美元套餐降到 30 美元（原帖）。Burn Watch 看剩余额度、消耗速度和最费额度的定时任务；Script This Routine 扫描定时任务，把简单重复的检查改成脚本，只在真正需要 AI 时才唤醒 Bot（他最推荐这一条）；dr eggbot 按职责创建 Bot 并做健康检查；Alfred 检查 Bot 是否职责重复；Projects Manager 用 Notion 给多个 Bot 分任务并跟踪进度。他提醒：这些 Bot 自己跑也要消耗额度，尤其是定时检查，要先看能否真正省额度再长期开
    前提或争议：这是社区整理的用法，不是 Grok Bot 官方功能；效果因各人的定时任务而异
    为什么值得看：你在用 Grok Bot，把「重复检查改成脚本、只在需要判断时才唤醒模型」这一步可以直接用在自己的例程和工作台上，避免额度耗在例行巡检上
  8. Akshay 认为并行 Agent 最常见的错是：代码分了分支，却让每个 Agent 直接写同一份共享数据，后写入的会无报错地盖掉先完成的结果（作者经验）：比如 Claude Code 和 Codex 同时读到同一条记录，Codex 先写完，Claude Code 仍按开始时的旧副本写回，下一次查询就看不到 Codex 的改动（原帖）。他推荐开源图数据库 Omnigraph：给 Agent 数据加上类似 Git 的分支和合并检查，策略禁止直接写 main，过期的合并会被拒绝并让 Agent 从最新 main 重试，Agent 可通过 MCP、TypeScript SDK 或命令行接入
    前提或争议：这是他的观察和对该项目的推荐，不是广泛评测；Omnigraph 的实际成熟度要以仓库和文档为准，原帖里的仓库链接在接口里没有展开成可点的地址
    为什么值得看：多 Agent 协作时，共享记忆和共享状态如果没有分支和合并检查，就会出现这种「谁也不报错、结果被静默覆盖」的坑，工作台的共享存储可以按这个边界来设计
