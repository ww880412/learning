今日主线
  1. Grok Bot 这周额度用得特别快，马斯克回应：服务成本相对收入「高得不可持续」：有用户在 X 上问能不能重置 Grok Bot 用量，说很多人这周提前用光；马斯克北京时间 11/2 凌晨回复「The cost of serving Grok Bot was unsustainably high relative to revenue」，Sawyer Merritt 转发时把它解读为这一周期部分用户更快撞到上限的原因（马斯克原帖、Sawyer 原帖、TeslaNorth 报道）
    前提或争议：只有马斯克一句回复。具体改了什么（每周额度变小，还是计费权重变了）、会不会给受影响用户重置、会不会调价，都没说，也没看到 xAI 或 Cursor 的公告；「限额收紧是有意调整」是媒体从他用过去时推出来的
    为什么值得看：你的 Grok Bot 上跑着简报、海报、课程监控这些 routine，额度变紧会直接影响能不能按时跑完。先看一眼设置里的 Usage，把高频 routine 和长时间浏览器操作排个优先级；工作台的额度计量要能按 Bot 和 routine 拆开看
  2. Linux 内核 TCP 漏洞 CVE-2026-98432：只要开着一个 IPv4 TCP 端口就可能被远程拿 root，Ubuntu 还没出补丁：levelsio 转引的帖子说，任何没打补丁、对公网开着一个 TCP 端口（HTTP 或 SSH 都算）、并启用了多路径 TCP（MPTCP，很多 Go 服务默认开）的 Linux 服务器都可能被完全接管；他再次建议 VPS 端口全关，SSH 只走 Tailscale，网站流量走 Cloudflare Tunnel。原始资料：内核 CNA 10/15 发布 CVE，CVSS 9.8，漏洞在 IPv4 TCP 握手里，4.4 起所有版本都受影响，上游 10/11–10/15 已修；报告人是 Anthropic 的 Xinyang Ge，Anthropic 称 Claude 写出了能在「带 MPTCP 监听的服务器」上远程拿 root 的利用代码（levelsio 原帖、alive_ 原帖、内核 CVE 公告、Atlas 报告、AWS 公告）
    前提或争议：Anthropic 演示的利用需要 MPTCP 监听，但漏洞本身在普通 IPv4 TCP 里，关掉 MPTCP 只是缓解；Go 1.24 起程序默认对监听开 MPTCP（Go 安全团队）。截至北京时间 11/2 08:15（Atlas 更新），Red Hat、Debian、Amazon Linux、Oracle UEK 已出补丁，Ubuntu 各版本仍标「Vulnerable」；AWS 称没发现在野利用，CISA KEV 未收录；GitHub 上已有至少 7 个仓库自称带竞态触发或 PoC（Atlas 统计，未验证）。打完补丁要重启才生效，容器看的是宿主机内核
    为什么值得看：你的 Mac 不受影响，但 VPS、开发机、跑 Agent 的云沙箱和 Kubernetes 节点都在范围里。可以直接抄的三步：ss -Mlnp 看有没有 MPTCP 监听、sysctl net.mptcp.enabled 不用就关；在 nftables 加一条丢弃带 IPv4 选项的 TCP 包；换补丁内核后重启。工作台给 Agent 开云机器时，内核补丁状态应该是可见字段
  3. Claude Code 终端版恢复 ultrathink：输入这个词，本轮升到 xhigh，干到一半也能加：Addy Osmani 提醒，任务比预想难时，在 Claude 干活时打 ultrathink，这一轮剩下的部分会提高 effort，需要终端最新版；转引的 dmwlff 说这个功能之前因为「怪、容易让人困惑」关过一阵，现在回来了，他平时用 Opus 5.5 medium，个别轮次再加码。swyx 补充 Karpathy 做 HackerTube 也是默认 Opus 5.5 medium，他认为 effort 档位之争就像「tab 还是空格」，按口味调就行（Addy 原帖、dmwlff 原帖、swyx 原帖、Claude Code 更新日志）
    前提或争议：官方已确认：更新日志写明 2.1.311 起，交互终端里的 ultrathink 会把本轮跑在 xhigh，只对通过 Anthropic API 的 Opus 5.5、Sonnet 5.5、Haiku 5.5 和 Fable 5.1 生效，Bedrock 上要用 /effort；CLAUDE_CODE_EFFORT_LEVEL 或 maxEffortLevel 设得比 xhigh 低时不会生效，可以用 CLAUDE_CODE_DISABLE_ULTRATHINK 关掉。同一份日志还加了 CLAUDE_CODE_SUBAGENT_EFFORT，让子 Agent 单独设 effort
    为什么值得看：「默认 medium、难的轮次临时加码」是省额度的直接做法；工作台如果用 headless 或 SDK 驱动 Claude Code，记得这个关键词只在交互终端生效，子 Agent 的 effort 可以用新变量单独压低
  4. Anthropic 每天合并约 3 万个 PR，靠的是「证据包」而不是人逐行读 diff：meng shao 整理 Addy Osmani 和 Manish 在 AI Engineer 的分享：Addy 称 Anthropic 日合并量从 5 月约 2500 涨到约 30000。流程是 Claude 先审一轮，再像真用户一样试产品（浏览器、lint、测试），用 hooks 盯编辑和 diff，团队约定写进 CLAUDE.md / AGENTS.md，人最后核对 Agent 交上来的端到端测试、截图和录屏。他强调只说「verify」太空，要落到端到端、property、视觉验证这些具体测法，才谈得上自动合并（meng shao 原帖）
    前提或争议：转述，3 万这个数字是 Addy 在台上说的，没有公开数据；CircleCI 那边的观察是 CI 吞吐大涨，但约三成合并尝试仍失败；SonarSource 提醒受监管场景里仍有相当比例代码没经过充分审查就进了生产。责任仍在发起人：「你让 Claude 跑完的，出事还是你修」
    为什么值得看：工作台的评审页可以照这个改：每个 Agent PR 必须附一个证据包（测试结果、截图或录屏、跑过哪些检查），人审证据，不审全部 diff；Agent 写的 PR 打标，加额外检查清单
  5. 编排 Bot 不写代码，只管「第一公里和最后一公里」；信任按倒金字塔往上堆：meng shao 整理 Rob 的视频（基于 poteto 和 Theo 的用法）：Grok Bot 这类编排 Bot 负责从 Slack、邮件、Linear 收齐「要做什么」，再追进度和验收；写代码交给有独立机器的 Claude Code、Cursor、Codex。Lauren 的日常环：Slack 发现 bug → 开 Linear 单 → Cursor 云 Agent 在独立机器复现 → 开「fix and fuzz」PR，让一小群 Agent 用随机点击和 Playwright 去打破修复 → 干净就通知，约一小时没人反对就自动合；支付这类关键路径按爆炸半径分红黄绿，不自动合（meng shao 原帖）
    前提或争议：观点和个人做法，「上千 PR、自动合」是视频里的转述，没有数据。Rob 提醒两点：编排 Bot 自己写代码会和 Cursor/Grok 共用额度池，容易烧光；Grok Bot 多个 Bot 共用一台云电脑（文件、浏览器会话、CLI 凭证），一个 Bot 登录的 key 别的 Bot 也可能用到
    为什么值得看：和你「Claude Code 出方案验收、Codex 实现」的分工是一个思路。倒金字塔可以直接当工作台的信任设计：代码库结构 → lint/测试/CI → AGENTS.md 和 skill → 人审放最后；每次纠正 Agent，就把修复往上挪一层
  6. Matt Pocock 预告 Sandcastle v1：把他的每个 skill 变成一个可调用的 Agent() 函数：Matt 征求意见的定位是「帮你搭软件工厂」：内置 6 种 harness（Claude Code、Codex 等）也能接自己的，接 Daytona、Vercel、E2B 等主流沙箱，带 Inngest / Trigger.dev 模板做可恢复的长流程，支持经 Slack 和 Discord 的人工审批，也支持无人值守；skills 仓库里每个 skill 会变成 CodeReview()、ImplementSpec()、Retro() 这样的函数（Matt 原帖、原帖、原帖）
    前提或争议：只是 pitch，v1 还没发布，Matt 自己说会大改；同一天他还说 Redux 式「状态只放一个地方」对 Agent 可能有好处，但承认状态总会分散在 URL 和服务端
    为什么值得看：你在做的 Matt 插件和工作台，正好对应这条路线：skill 不只是给模型读的说明，而是带输入输出、能编排、能放进可恢复工作流的函数。可以先抄「skill → 函数签名 → 跑在你自己的沙箱上」这一层
  7. 微软开源 4B 桌面 Agent 模型 Mage-VL-Cowork：模型自己决定这一步点界面还是写脚本：一笔整理：视觉布局、画布这类操作走 computer_use（11 个 GUI 原语），表格、文档这类结构化编辑和完成后的校验走 bash 加 Python；OSWorld-Verified 66.0%，高于同表 Qwen3.6-27B 的 63.9%，但低于 ScaleCUA-Qwen3.5-9B 的 68.7%。训练里最值得抄的一步：先修老师的 harness，删掉 xdotool、冗长无障碍树这类重复通道、预装领域 Python 库，GPT-5.4 老师升到 92.0%、步骤少 29.2%，学生对应高 12.5 个百分点（一笔 原帖、原帖、Hugging Face 模型页）
    前提或争议：分数是厂商自报，还没看到外部在相同条件下重跑；调用次数和 token 减少不等于用户等待时间缩短；训练用了 32 张 B200，小模型省的是推理钱。Apache-2.0，权重约 9.48 GB
    为什么值得看：两条能直接用在工作台：一是工具越多不一定越好，重复工具会教坏模型，先删冗余通道；二是评测别只看成功率，还要看 Agent 选的路径是否合理、交付的文件是否真的对
  8. 字节扣子企业版分阶段下线：11/30 停止新售，旧版套餐 12/31 下线：火山引擎 10/29 发公告，因「产品整合安排」，扣子企业标准版、旗舰版 11/30 起不再卖给新客户，在火山引擎买的旧个人进阶版、旧企业版、旧团队版 12/31 全面下线并退还未用部分，新版企业套餐最晚用到 2027-12-31；对话、记忆、文件、低代码工作流怎么导出「另行公告」。Orange AI 认为「扣子的故事结束了」，同时结束的还有字节好几条 AI 产品线，大厂产品寿命可能还不如创业公司（Orange AI 原帖、扣子企业版下线公告）
    前提或争议：官方公告只说企业版下线，扣子本身的个人产品仍在；后续给企业客户的替代方案「正在规划」，还没公布。「字节 N 条 AI 产品线结束」是 Orange 的说法，他没列具体是哪些
    为什么值得看：企业买 Agent 平台最怕的就是这种整合下线：数据和工作流导不出来。工作台对企业客户讲的「资产归你」，要能落到对话、记忆、工作流的可导出格式上
