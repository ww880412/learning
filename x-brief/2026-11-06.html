X 简报 · 11/7（周六）

今日主线
  1. Claude Code 曾把登录账号邮箱放进模型上下文，Agent 有时写进 User-Agent 发往网站；Addy 承认不该发生，下周一左右版本会从上下文去掉邮箱；2.1.317+ 对含邮箱的 web/curl 会先询问，但仍拦不住它自己写脚本再跑（Anthropic 工程师回应 + 用户曝光）：midudev 演示访问某些站时个人邮箱出现在 User-Agent；Addy 解释部分 API/站点要求联系邮箱，于是把账号邮箱塞进上下文，模型写命令时会带上。临时缓解是升到 2.1.317+ 并尽快跟正式去掉上下文的版本（Addy 原帖、midudev 原帖）
    前提或争议：厂商工程师公开承认与排期；2.1.317 的询问并不能覆盖「脚本里再发请求」；未看到独立 CVE 编号
    为什么值得看：直接打在「Agent 出站会带什么身份」上。可抄：默认不把真实账号邮箱放进 Agent 上下文；出站请求用专用联系邮箱或空 User-Agent；对 curl/脚本做邮箱与密钥扫描再放行
  2. Claude Code 云会话（Pro/Max/Ultra）：官方称 Claude 会自行弄清依赖、网络权限和所需 API Key，并保存环境供下次复用；API Key 安全存放，Claude 看不到明文（ClaudeDevs 官方）：视频演示一键把仓库跑起来；TestingCatalog 同步报道（ClaudeDevs 原帖、TestingCatalog 原帖）
    前提或争议：官方自报能力与密钥隔离说法；适用套餐与具体保存位置以产品界面为准，尚未看到独立安全审计
    为什么值得看：和上面「邮箱进上下文」同一天对照——一边补权限泄露，一边把云环境配置自动化。工作台可抄：依赖/网络/密钥三张清单单独存，密钥只进密钥库不进模型上下文；首次跑通后固化环境快照
  3. Shopify Reflex：为「Agent 写大部分代码」重做的移动端架构——业务逻辑无 UI、ViewModel 统一暴露状态与动作，CLI 无模拟器即可驱动双端行为测试；官方称 1700+ 条行为测试双端 CI 约 4 分钟（Shopify 工程博客，11/5）：原则是「共享测试，不共享代码」；Swift/Kotlin 各写一遍，同一份行为测试两边都过才能合入；不测像素，视觉另做。meng shao 中文拆解（ShopifyEng 原帖、官方博客、meng shao 原帖）
    前提或争议：厂商自报数字与架构；博客写明不准备发成库，要团队按文自建；不替代截图/设计走查
    为什么值得看：把昨天「可验证性」从提示词落到产品结构。可抄：核心层可无界面跑；每个屏一个「状态 JSON + 动作列表」合同；Agent 用 CLI/ls/do 验逻辑，像素另开闸门
  4. Harness Leaderboard：同模型换 harness，成绩差一截；28,849 次试验、约 4746 美元推理；平均下来 mini-swe-agent 约 51.4%、Pi 约 49.4% 且每解一题约 0.29 美元，OpenCode 约 3.35 美元/题（作者自测排行榜）：固定模型/供应商/推理力度，只换 harness，每题 3 次；最佳 harness 随模型变。Thom Wolf 转发「同一开源模型，不同 harness → 结果很不同」（Joël 原帖、排行榜、Harness Lens、Thom 原帖）
    前提或争议：作者自费评测，任务集是 Terminal-Bench 2.1 与 DeepSWE，不代表你的企业仓库；数字会随版本漂移
    为什么值得看：工作台选默认 harness 不能只看品牌。可抄：同一模型固定后做一小套私有任务横评；同时看解题率与美元/题；用 Harness Lens 对照提示词、工具与压缩策略
  5. 宝玉：把「PR 必须带功能截图」套到 Agent——任务结束先自测并交效果截图；截图过程里 Agent 常自己发现问题并顺手修（作者经验）：呼应昨天 Addy「人审证据」与 Matt「fully verifiable」（宝玉 原帖）
    前提或争议：个人工作流，没有对照实验；截图不等于权限与安全验收
    为什么值得看：一行就能写进工作台收尾清单。可抄：完成定义加上「附浏览器/界面证据」；证据进 PR 说明，不进「口头说测过了」
  6. Thariq：喜欢的模式——Instagram Edits、Roblox Studio 这类创作工具内置 MCP，Agent 干一部分，高手仍在熟悉工具里接手（个人观察）：另提到 webMCP（页面自注册工具）在 Chrome/Edge 源试验（Thariq 原帖）
    前提或争议：模式观察，不是 Anthropic 产品公告；具体 App 的 MCP 覆盖面未逐一核实
    为什么值得看：企业工作台可做成「Agent 可编程的专业工具」而不是另起聊天窗。可抄：每个重工具暴露稳定 MCP/工具面，人和 Agent 共用同一套动作
  7. Max Leiter 正式宣布做 Claude Code Desktop，公开求反馈；Addy 等团队成员互动（本人声明）：同日桌面端体验仍被社区吐槽（Max 原帖、Addy 互动）
    前提或争议：人事/职责自报，不是功能发布；Desktop 路线图与时间表未给
    为什么值得看：Claude Code 客户端有了明确对接人。可抄：把 Desktop 卡点（搜索会话、权限提示、更新通道）整理成可提交反馈清单
  8. Tibo：人类不擅长写安全基础设施，终点应是人人可用的超安全软硬件，但中间会颠簸；并称千万行级形式化证明已不再荒谬，设计新系统时应纳入考虑（个人判断）：贴在 GPT-6 Cyber 发布后的讨论流里（Tibo 原帖、跟帖）
    前提或争议：观点帖，不是产品规格；「千万行证明」没有附公开案例与工具链细节
    为什么值得看：和昨天 Cyber / microVM 同一条线——能力上升后，默认假设要改成「人写的安全边界不够」。工作台可预留：关键路径可形式化/属性测试的接口，而不是只靠事后扫描
