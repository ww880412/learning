X 简报 · 11/22（周日）

今日主线
  1. OpenRouter 发给用户的邮件称，经 MiniMax 路径的请求可能被第三方读到；Novita 公告确认部分请求被转到 MiniMax 官方 API（OpenRouter 邮件为公开转述，Novita 为官方公告）：安全研究员在 2026 年 7 月至 10 月发往 MiniMax 的提示词里放入一次性测试链接，这些链接在请求发出 40–130 小时后被打开；OpenRouter 称 AtlasCloud、Novita、StreamLake 曾把 OpenRouter 的 MiniMax 请求转给 MiniMax，并表示问题在 MiniMax 及向其转发的服务商，不在 OpenRouter，同时去掉了相关接口的 Zero Data Retention 标识。Novita 11/22（北京时间）公告说，2026-05-28 至 2026-11-11 经 Novita 的部分 MiniMax 请求（含经 OpenRouter 转来的）被转到 MiniMax 官方 API，而不是在 Novita 自己的基础设施上处理，已暂停受影响模型，并建议轮换提示词里出现过的密钥。公告还写，访问模式「可能涉及自动内容审查」，仍在与 MiniMax 核实（swyx、Sebastian Raschka 的解释、一条整理帖、Novita 公告、Hacker News 上的邮件转述）
    前提或争议：我没有看到 OpenRouter 官方博客，邮件正文来自公开转述；目前没看到 MiniMax 官方说明。swyx 问这是不是「偷偷回传」，这是他的疑问，不是已证实的结论。Raschka 的解释是：OpenRouter 常选最便宜的推理商，对方满载时会把流量转到官方 MiniMax
    为什么值得看：工作台如果经聚合路由调模型，ZDR 标签和实际转发路径可能不是一回事；提示词里不要放密钥，已经走过受影响路径的要把密钥换掉
  2. Google 人员 Varun 称，Antigravity 已重置全员 Gemini 配额，缓存改进使同等配额可多完成约 22%（官方人员自报）：他此前说，给 Neon 在 Antigravity 上大幅扩容缓存池，缓存命中率约提升 4%，同等配额至少多完成 20%，并预告因之前消耗过快、完成后会重置一次；随后宣布重置已经完成，可完成量提高 22%，欢迎周末用 Neon。testingcatalog 和宝玉都转发了（重置宣布、此前的缓存说明、testingcatalog、宝玉）
    前提或争议：22% 是 Google 人员自报，不是产品文档里的正式承诺；宝玉提醒，关心这次重置应看 Varun 的说明，而不是 Tibo
    为什么值得看：在 Antigravity 里用 Neon 的人，配额和缓存命中会直接改变能跑完的任务量；周末如果觉得额度突然回来了，这是官方给出的原因
  3. LangChain 官方文章谈「知识工厂」：内部 Agent 都有学习闭环，知识更新交给单独的 curator agent（官方文章）：Harrison Chase 写长文称，公司要用好 Agent，缺的往往不是更好的模型，而是可维护的公司知识——怎么干活的 skills、不太变的领域知识、数据在哪、怎么查。LangChain 内部的 GTM、内容 Agent 和 LangSmith Engine 都按这套思路做。做法是：干活的 Agent 只负责标记缺失或错误；后台 curator agent 按节奏去读原始来源和 traces，再更新知识库。不要让干活的 Agent 自己改 wiki，否则容易乱、会互相矛盾。存储可以是 GitHub 里的 skills、Notion 或 LangSmith Context Hub 等。他在回复里补充：skills 这类常见要人签字，其他形式的记忆可以自动合并（原帖、X 长文、关于 curator 的补充、skills 需人审）
    前提或争议：这是 LangChain 的内部做法和产品观，不是通用标准；存储格式他写明还没有行业共识
    为什么值得看：企业级 coding agent 工作台可直接抄两步：给干活的 Agent 一个「标记知识有问题」的工具，另设一个只负责改知识库的 curator，skills 更新先留人审
  4. Logan 说明 Gemini 4 怎么选：Carbon 是「大模型的味道」，Neon 最全面，Hydrogen 又快又省；没必要再用 Argon（官方人员口头说明）：有人问 Carbon、Neon、Argon 和 Hydrogen 该怎么搭配，Logan 这样划分，并在另一条回复里明确「改用 Carbon 或 Neon，现在没理由再用 Argon，那只是 Gemini 4 的第一版」。Simon Willison 用同一只「鹈鹕」图测试 Hydrogen：high 思考花费 3.99 美分、5311 个输出 token，xhigh 花费 23.61 美分、31477 个输出 token，他认为两者差别非常大，并贴了 Carbon / Neon / Hydrogen 在各思考档位的对照图（Logan 的分档说明、关于 Argon、Simon 的 Hydrogen 测试、对照图）
    前提或争议：分档是 Logan 在回复里说的，不是产品文档；Simon 的价格和 token 数来自他这一次测试，不能当成官方价目表
    为什么值得看：工作台如果接入 Gemini 4，默认选型和思考档会显著影响成本和延迟；Argon 可以从默认列表里拿掉，Hydrogen 的 xhigh 要按效果单独衡量
  5. Claude Code 2.1.330 增加内置模组 easel，可按要求画图，也可为 MCP 指标结果自动出图（官方更新日志，11/20）：changelog 写明面向 Pro、Max，Team 和 Enterprise 视情况提供，目前在 macOS 和 Linux；可在 /config 关掉自动出图，也可在 /plugin 关掉整个模组。同一版本还加入了通过企业 Admin Console 登录、自托管 runner 的起始目录，以及 VS Code 里的 /fork、/workflows 等。testingcatalog 今天在每日简报里也转述了 easel（官方 changelog）
    前提或争议：官方日志日期是 11/20，关注名单里今天才出现转述；自动出图默认开启，不需要的要自己关
    为什么值得看：做工作台评测或看 MCP 指标时，可以直接让 Claude Code 出图；企业登录路径也从这一版开始对接到 Admin Console
  6. Lean 与 Mathlib 社区发表联合声明，并经 Lean FRO 和 Mathlib Initiative 背书，认定 Alpöge 的黎曼猜想 Lean 证明通过形式化核验（官方声明）：声明写，Levent Alpöge 于 11/20 交出约 1700 万行 Lean 库；社区核验后「充分相信」该证明正确，并证明它证的就是 Mathlib 里已由专家审过的 RiemannHypothesis 语句。四条标准都满足：语句正确、库能复现编译、两个独立工具确认所证定理与 Mathlib 语句一致，以及 Lean 官方内核和多个独立检查器（含带形式化正确性证明的检查器）通过了导出证明。声明最后说，期待数学界继续把证明里的新想法讲清楚。关注名单里，deedydas、歸藏等转发了 Lean 官方账号的声明（Lean 官方帖、社区声明、核验说明页、deedydas、歸藏）
    前提或争议：这是机器检查通过，不是传统的人类同行评审；声明谈的是黎曼猜想，不是广义黎曼猜想，deedydas 写「GRH has fallen」是他的说法。人类是否已经理解这 1700 万行里的新想法，声明自己也把「解释」留作下一步
    为什么值得看：昨天还只是作者自报、没有独立核验；今天多了形式化数学社区的官方背书。对工作台的启发是：先把要验收的语句写死、再让机器检查，比事后用肉眼审完所有生成结果更关键
