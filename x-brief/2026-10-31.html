X 简报 · 11/1（周日）

今日主线
  1. 用 claude -p 跑 Claude Code，5 小时额度扣得比 TUI 快约 1.8 倍；Magpie 改为驱动 TUI：yetone 宣布 Magpie 的 Claude Code Provider 从调用 claude -p 改成直接驱动 Claude Code TUI（可配置切回），理由有两条：有人发现 -p 在 5 小时窗口下比 TUI 多花约两倍额度；走 TUI 和用户直接用官方客户端完全一样，几乎不会被判成第三方使用而封号。原始报告是 GitHub issue #97074：Max 订阅下同样的工作量，headless 模式（会话记录里 entrypoint 记为 sdk-cli）占用 5 小时窗口约是交互模式 cli 的 1.8 倍，token 数相同（yetone 原帖、宝玉转发 原帖、GitHub issue #97074）
    前提或争议：只涉及 5 小时窗口的计量；倍数是用户自测，各家测出 1.6–2.9 倍不等，社区转述的对照里周额度消耗相同。issue 9/25 开出、60 条评论，至今没有 Anthropic 成员回复；官方帮助页只说 -p 也计入订阅额度，没说权重不同。评论区流传的「把 CLAUDE_CODE_ENTRYPOINT 改成自定义名字就能拉平」也是用户自测，可能被看成规避计量。验证过的 Ultra 账号已取消 5 小时窗口，Pro 和 Max 仍有
    为什么值得看：工作台如果用 headless 方式驱动 Claude Code、走订阅额度，先拿会话 jsonl 里的 entrypoint 字段做一次同任务 A/B 记账，别默认两种入口扣得一样；改 entrypoint 这种做法等官方表态再定，免得撞上使用政策
  2. Grok Bot 本地执行设成「始终允许」后，云端做不了的事会直接落到你的电脑上：小墨同学说他遇到过两次：GitHub CI 在云端失败后，Bot 直接到他本地电脑上跑，电脑发烫；网站校验页过不去时，Bot 直接用他本机的浏览器去操作。他建议本地电脑和其他连接的电脑都设成「每次询问」或「始终不允许」，没有特殊网络需求就关掉「经此电脑转发流量」，否则可能暴露本地出口 IP（小墨同学 原帖、官方文档）
    前提或争议：作者自报，前提是他之前选了「始终允许」。官方文档写明默认是「每次询问」；选「始终允许」后所有 Bot 跑本地命令都不再逐条确认；官方建议没有明确理由就选「始终不允许」，团队管理员可以统一封顶。这是设计行为，不是漏洞
    为什么值得看：你的 Grok Bot 连着 Mac 的话，可以去 设置 → Computer 看一眼这一项。工作台可以抄这条边界：云端失败回退到本地机器时必须重新征求同意，并在审计里记下是哪台机器执行的
  3. Codex：手机端能切换多个账号，Tibo 最后两天发放「存好的」重置：Codex 负责人 Tibo 在 28 天连更的第 26 天宣布，手机端可以方便地在多个 ChatGPT 账号之间切换，桌面端即将支持；并说接下来两天会有重置，「已经存好了，你们看着用」。北京时间 11/1 早上他发了「Banked 1/2」（Tibo 原帖、原帖、宝玉 原帖、多账号帮助文档）
    前提或争议：多账号切换是官方发布，有帮助文档；「banked」具体是自动重置用量还是能留着以后用，Tibo 没说清，宝玉理解为「最后两天送重置卡」；12 月 ChatGPT 和 Codex 可能共用额度，目前仍只见于结账页的隐藏文案
    为什么值得看：多账号切换进了官方客户端，「一个人用几个账号分工跑 Codex」成了正常用法，工作台的账号和额度管理可以按多账号设计；这两天有大任务排队的话，可以趁重置跑掉
  4. IBM 论文：在 Agent 和工具之间加一道决策闸门，τ²-bench Telecom 成功率从 39.5% 升到 80.7%：elvis 介绍 IBM 的 JevAct：先让 LLM 把领域政策翻成代码检查和一组是/否问题；选定的工具调用执行前，代码去核对工具记录里的事实，一个类似 Jev 的决策模型回答关于对话的问题，不通过就带着反馈退回给 Agent 修改。模型和工具都不变；Opus 4.6 在 Telecom 上三次全部成功的比例从 39.5% 升到 80.7%，8 个 Agent 平均提升 16.9 分，BFCL 上 9 个全部提升（elvis 原帖）
    前提或争议：数字是论文自报，elvis 转述；Airline 场景提升小，有升有降；闸门只拦「选定的」工具调用
    为什么值得看：这是权限层可以直接抄的结构：政策 → 可执行的检查和是非问题 → 调用前拦截 → 不通过就把理由退回给 Agent 重试，而不是一拒了之。可以先从「高风险工具调用前跑一遍代码检查」做起
  5. DeepSeek Harness 团队公开 Super-agent 设计：Router 管分派、Worker 干活，人只做决策和验收：meng shao 整理了 DSH 团队的架构文章。他们认为瓶颈已经从模型变成人：一个人大约只盯得住 3–5 个活跃 Session。做法是：常驻 Router 统一对人说话和分派任务（可以用轻模型，甚至不挂 Bash），Worker 上下文隔离、挂满工具；群聊、邮件、CI 这类 Trigger 先过确定性规则，再交给 LLM 判断，同一个 PR 或话题订阅后，后续事件直接交给对应 Worker；耗时工具改成异步 start/stop；Loop 放在云端，Session 状态进数据库，端侧只跑没有会话状态的 daemon；另有独立 Watchdog 看 Worker 有没有实质进展（meng shao 原帖）
    前提或争议：只有原型（dsh-superagent-prototype）和合成负载实验：约 300 条消息、20 个任务，完成时间 p50/p95 约 12.4/15.7 分钟，「单 Session + Subagent」的 p95 约 29.5 分钟，代价是读缓存 token 更多；异步 ReAct 已实现但默认没开；凭据、入侵面、跨月记忆，团队自己写明还没解决
    为什么值得看：几乎是工作台多会话编排的现成蓝图。最值得先抄两步：同一 Thread 订阅后事件直接交给 Worker（实验里 Router 决定少了约 30%），以及「云端无状态 Loop + 端侧 daemon」，把计算和本地凭据分开
  6. Meta FAIR：任务交错时一条全局记忆几乎没用，按簇分开记，奖励升、成本降六七成：DAIR.AI 介绍了 Meta FAIR 的 Routed Continual Learning（elvis 转推）：任务交错时，一条全局历史比完全不用记忆只高 0.015（归一化奖励）；改成把过往轨迹聚成簇，每簇用固定记忆系统库里的一种存状态，每次运行前由 LLM 路由选簇或新建。在 301 个 CL-Bench 和 97 个 τ³-Bench 银行任务混在一起的流上、4 个模型，奖励比全局历史多出最大可得奖励的 15%–30%，估算 API 成本降 65%–72%（DAIR.AI 原帖、elvis 转推 原帖）
    前提或争议：转述，数字来自论文；实验都是顺序执行，多个 Agent 并行更新同一簇没测
    为什么值得看：工作台的记忆如果是「一个项目一条大历史」，先别急着换更大的记忆系统，试试「按任务类型分簇 + 运行前路由」这一步
  7. LangChain 两人回应「harness 已经没意思了」：还有一长串要做：Harrison Chase 发长文《2026 年底新的上下文工程难题》，认为大家都收敛到「LLM 循环调工具、跑在沙箱里」，标准问题有了标准解，但新问题正在冒出来。他转发的同事 Vtrivedy10 列了一张 harness 清单：给常用流程做专用工具或 skill，一次调用就完成、省上下文；按场景调压缩阈值；用 subagent 或路由把部分工作交给便宜模型；做连接器；支持后台任务，让用户先拿到反馈；做对用户真正有用的记忆；再用信得过的评测集，在新模型上自动调 harness（Harrison 原帖、Vtrivedy10 原帖、Harrison 转推 原帖）
    前提或争议：都是观点，LangChain 本身卖 harness 和可观测工具，立场明显；Harrison 的长文我们只读到开头一段
    为什么值得看：Vtrivedy10 这张清单可以直接当工作台 harness 的自检表；最后一条「用信得过的评测集自动调 harness」，是每次换模型时最省事的做法
  8. Google Antigravity 下周可能上线云端执行，产品里新加了数据外泄风险提示：TestingCatalog 称 Antigravity 可能下周支持云端执行，任务可以在本地和云端环境之间切换；这是 Jules 宣布关停、能力并入 Antigravity 之后的下一步，官方另外预告了下周「Antigravity 大发布」。同一天它还发现 Antigravity 加了一条提示：「AI 编码 Agent 有已知的安全局限，包括数据外泄和可能的代码执行；避免处理高度敏感的数据，并核对 Agent 的所有操作。」（TestingCatalog 原帖、原帖、原帖、TestingCatalog 报道）
    前提或争议：爆料，云端执行没有官方公告；安全提示是在产品里看到的文案，没附具体漏洞，也没有 CVE
    为什么值得看：本地和云端可切换的执行面，正是工作台要做的；厂商把「可能外泄、请核对每个动作」直接写进产品，等于把责任压到用户确认这一环，工作台的审批卡和操作日志要接得住
