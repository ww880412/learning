Claude Managed Agents 工作坊
这场工作坊一句话讲什么？

把 agent 拆成会话日志、大脑、手三个接口

会话日志（session，只追加的事件记录）最持久；大脑（Claude 加 agent 循环）不存状态；手（沙箱和工具）用完就扔。

拆开后，只有会话日志值得保护，其他部件坏了都能重开。

讲者 Priyanka Phatak 讲架构（前 11 分钟），Gabe Cemaj 带动手部分 Research Desk。工作坊产品名是 Claude Managed Agents（CMA），Anthropic 托管 harness、沙箱、扩容和事件日志存储。

机制：坏了怎么恢复？

沙箱和 harness 坏了都能直接换新的

沙箱挂了，Claude 在新容器上重试；harness 挂了，新 harness 读回日志接着做。

机制：上下文满了怎么办？

会话日志比上下文窗口活得久

# 4 对话：同一条事件流
POST /v1/sessions/{id}/events   user.message / user.interrupt ...
GET  /v1/sessions/{id}/stream   agent.tool_use / session.status_idle ...
API 怎么用？

四步：环境、agent、会话、事件流

agent 定义不知道自己会跑在哪个环境上；会话把两者绑在一起。

会话创建后是 idle，发事件之前什么都不发生。

你发的事件：user.message、user.custom_tool_result、user.tool_confirmation、user.interrupt。你收的事件：agent.message、agent.tool_use、agent.custom_tool_use、agent.mcp_tool_use、session.status_idle（带 stop_reason）、session.error。Console 演示里一句「build me an agent that tells me jokes」就生成了 prompt、名字和模型。
