讲者备注：到目前为止大家驾驭的都是小型开放模型，主要是自己机器上的 9B，上下文 32K。今晚每次模型调用都去 gpt-5.6-luna：OpenAI 的模型，经 U-M GPT Toolkit 提供，是另一个级别的模型，写代码强得多；昨天实测端到端约每秒 80 个 token。

所以今晚是两小时真正的构建，而不是两小时和模型较劲。但有一行没变，就是下一页。

一个怪现象：Toolkit 会把流式回复在最后一次性交出来，长回答会先几秒什么都不显示，然后全部出现。那是网关的行为，不是你的代码有问题。

给讲者的提示：数字来自 hackathons/toolkit-models.md，9 月 23 日实测。

强模型，跑在你熟悉的 32K 预算上。

讲者备注：Luna 能接收超过一百万 token 的上下文。今晚你拿到的是三万两千，和整学期一样——在 Aider 里如此，在你自己代码发出的模型调用里也如此。

这是有意的：Aider 设为 32K，对话超出就警告；仓库里的模型调用会拒绝任何超过 32K 的请求，这个上限不归你改。所以照 aider-practice 以来的做法：对话里只放正在改的文件，其余丢掉，任务之间清空对话。

为什么要拿走百万 token 的窗口？因为决定把什么放到模型面前，正是这门课要教的本事。巨大的窗口会让马虎的习惯藏起来，直到会话变慢、变贵、变糊涂。今晚模型好得多，你仍照以前的方式工作。

第 10 页 · Given: taskr/model.py

这段调用已经在仓库里，你不用写，只要调用它

body = {"model": "gpt-5.6-luna", "messages": messages}

上面摘的是幻灯片代码的第一行：请求体写明模型并带上对话；下一步是传了工具时再附上 tools（模型可以请求执行的动作）。后面几行依次是：请求头里放 Content-Type 和 Authorization: Bearer 加你的 Toolkit 密钥；POST 到 base_url + "/chat/completions"（base_url 已以 /v1 结尾）；读出 JSON 回复，取 reply["choices"][0]["message"]，其中要么是 content，要么是 tool_calls。

你的调用方式：call(messages, base_url=..., model=..., api_key=..., tools=...)。

讲者备注：这就是完整的模型调用，已经在仓库的 taskr/model.py 里，每一步都有注释。你不写它，你调用它。自上而下：请求体点名模型、带着对话，传了工具时还带上工具——这就是 L07 的请求对象。

密钥放在 Authorization 头里，写成 Bearer 再加密钥。自己写这段时，大家最常写错的就是这一行。

它 POST 到 base URL 加 /chat/completions，base URL 已经以 /v1 结尾。回复的 message 在第一个 choice 里：要么 content 里有文本，要么因为模型要执行动作而带着 tool_calls。

你的代码把消息、工具和 .env 里的设置交给 call，拿回那条 message。密钥错了会返回「model HTTP error 401」，而错误信息里永远不会出现密钥本身。

花光 $25 的方式：一遍又一遍调用模型，没有任何东西让它停下。

讲者备注：昨天用脚本模拟一个强学生把整晚跑了一遍，Aider 同样限在 32K，总共 24 美分；单次最大的请求约 22 thousand（两万两千）token，所以 32K 从没挡路。

一个典型的晚上约一美元；把所有东西跑很多遍的人，两到四美元。

所以只有一种方式会花光 $25，而防住它是你的事：任何反复调用模型、又没有东西让它停下的代码，每次都发送更长的对话。每次调用都比上一次贵，一个跑了整晚的这种循环可以花光整把密钥。

Aider 会打印每条消息的花费，扫一眼。

第 12 页 · Working with Luna

守住 32K、小步提交、「Add file to the chat?」通常答 N

守住 32K 预算：/drop 掉文件，任务之间 /clear。

小步提交（commits）：每次一个能用的步骤。

「Add file to the chat?」：通常答 N。

讲者备注：在 32K 内，Aider 需要的照料和以前一样：对话里只留正在改的文件，其余丢掉，任务之间清空。Aider 警告对话超过 32K 时，那是让你清空的信号，不是让你点「是」。

有一个提示要答「否」：Luna 的回复提到一个不在对话里的文件时，Aider 会问「Add file to the chat?」。如果回复只是提到它，就答 N。答「是」会把回复重新发回去而不应用其中的编辑，改动就丢了。测试时这一点让同一个编辑做了两遍。

小步提交能用的步骤。Aider 会替你提交，步子越小，撤销越容易。

第 17 页 · Evidence

Aider 的对话随每次提交保存，每次提交都快照到 safety 分支

Aider 的每次提交都带上它的对话（conversation）。

每次提交都快照到 safety/<machine>。

/undo 照常可用，被撤销的改动也会保留（kept）。

bin/aider-log 把这些全部列出来。

讲者备注：你的 Aider 记录是计分的证据，而且永远不用记着去提交它。Aider 的每次提交都带着 .aider.chat.history.md，也就是产生那次改动的对话。

每次提交还会往一个以 safety 加你机器名命名的分支加一个快照，并在后台推到 GitHub。九点时笔记本没电，你的工作也已经在 GitHub 上。

/undo 和你熟悉的完全一样；撤销的改动留在 safety 分支上，你试过的东西都不会丢，用 undo 不必小心翼翼。bin/aider-log 显示 Aider 做过的每个改动和背后的提示词，包括撤销掉的。
