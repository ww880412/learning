A5：有限的上限；A4：代码里的一道检查

A5：有限的上限——停下来，并说明还有什么没解决。

A4：代码里的一道检查——一个「不」是一个答案，不是一个错误。

Hackathon 1（周四）围绕带类型的动作（typed actions）搭建；下周换成一段 shell 字符串。

讲者备注：周四晚上每个人都为一个更小的问题回答过这两个问题。A5 是第一个问题：运行为什么结束。它要求在有限上限后停下，并告诉用户还有什么没解决；还有两句可能被你略过：不要盲目重复先前成功过的改动；模型调用可能失败（Toolkit 偶尔的 502），要处理它且不丢对话。一个上限、一个「重复调用」的近亲、一个端点失败——那一段里已经藏着今天三种退出。

A4 是第二个问题：动作之前站着什么。每次写入都要过代码里的一道检查，绝不只靠提示词；在 ask 模式下用户看到改动、批准了才发生；一个「不」让 Taskr 保持不变，并作为该动作的结果交回模型。大家都用过它：SCENARIO.md 第 4 步要求第一次被要求改动时说不。讲者会问：你的模型拿到「不」之后做了什么？收两个回答。

周四有三件事原样带进下周：检查住在代码里，提示词说服不了它；「不」是答案不是错误，模型把它当结果拿到、运行继续；每个调用恰好对应一条 tool 消息，不管被拒与否，否则 API 会拒收这段对话。

有三件事不带过去：周四读操作从不询问，下周要问（下半场讲原因）；bypass 模式会不问就批准所有写入，下周没有 bypass，第 6 周的规则文件才是介于「什么都问」和「什么都不问」之间的东西。第三件就是今天的主题：周四的改动是带类型的（把这块移到三号、把那个任务标为完成），名字就告诉你效果；下周的动作是 run_command，唯一的参数是一段 shell 字符串——字符串本身就是动作。

给讲者的提示：这里不要问各自的上限是多少，那是课间题。好的回答包括：它问了为什么、它提出了别的办法、它说这活儿放不下。有人说模型又要了同一个改动，就说「先记着，十分钟后它有个名字」——那是重复调用；有人说程序在「不」上崩了，那是 A4 没达标，下周代价更高。

三种完成信号

原文 · Three done signals

No tool call：免费，但沉默不等于完成（Silent is not finished）。

A finish tool：有意说出的完成，每次请求约多 ~100 个 token。

Verification：模型声称完成，再由 harness 检查（checked）。

讲者备注：三种设计值得比较。没有工具调用——免费，每个模型都会；弱点是「没有调用」不等于「做出了完成的声明」。

finish 工具：给模型一个带 summary 参数的 finish，只把调用它当作完成，于是完成成了模型有意说出的事。代价是多一个工具定义，每次请求约一百个 token（L07 实测三个工具是四百）；小模型有时会过早调用它。

验证：模型声称完成，harness 去检查——接受声明前先跑测试。这是 L07 的第二个修正，把声明变成观察。提示讲者别停，下一页就是第一张卡片失效的地方。

最便宜、也最粗的兜底

其余五个的兜底（backstop）。

最粗的一个（bluntest）：L07 的那个 9。

你的决定：数请求，还是数工具调用（tool calls）？

讲者备注：步数上限拦的是明显的失控——模型一直在要、没有别的东西结束它；它是最便宜的检查，也是其他所有检查的兜底。它也是最粗的：L07 的运行就以它结束，在损害之后、工作之前，而且没人选过 9。

其中一个决定：什么算一步？一次模型请求，还是一次工具调用？一条回复可能带三个并行调用，两种计数会越差越远。哪种都行，但要写下来，因为同一个阈值在两种算法下意义不同。

第 14 页

步数上限拦不住上下文在增长的循环

L07：九步里从 471 涨到 3252 个 token。

一次大文件读取：一步就 +10,000。

在请求发出之前检查（before the request）。

你的决定：算下一个请求，还是整次运行的总量（run total）？

讲者备注：步数上限拦不住上下文在增长的循环。L07 的提示从 471 个 token 涨到 3252，九步里涨了七倍；九步这样还无害，但一次读大文件的 read_file，或者一次输出是整份测试日志的 run_command，一步就加一万，步数上限不会察觉。

在请求发出前检查：上一条回复的 prompt tokens 加 completion tokens，再加上之后追加内容的估算。usage 是 L07 讲过的真值，所以第一次之后的每次检查都锚定在一个真实数字上。

这个名字下有两个数，选一个：下一个请求的大小保护上下文窗口（2.4 指的是这个）；整次运行的总量保护你的钱包——周四的 Toolkit 密钥上那是真钱，hackathon README 说花光 25 美元的方式就是一个没有步数上限的模型循环；本地模型上，它是时间。v0 没有压缩（compaction）：大小检查一触发，运行就结束，不会总结后继续。

原文 Token budget
第 15 页

卡住的命令不发请求，所以不算步数、不花 token

常见的卡法：flask run、一个 watcher、git commit 打开的编辑器（editor）。

没有请求，所以没有步数，也没有 token（No request）。

每条命令一个超时，外加整次运行的预算（timeout）。

关闭标准输入（Standard input）。

讲者备注：前两者都拦不住卡住的命令：模型运行了一个永不退出的东西，没有新请求，所以不算步、不花 token。候选都很普通：watch 模式的测试运行器；git commit 打开编辑器；一条等标准输入的命令；在带 Flask 前端的仓库里（aider-practice 第 11 到 16 课就有），模型为了测试 web 改动会启动 flask run，而它永远不返回。

在步与步之间检查的运行级时钟打断不了这些，因为循环正卡在 execute 里。所以墙钟是两个机制：每条命令和每次模型请求都有超时，再加整次运行的预算。每条命令都关闭标准输入，等 stdin 的情况就变成立即报错而不是挂起。

一个注意点：关闭标准输入只修好读标准输入的程序，修不了编辑器。不带 message 的 git commit 会打开编辑器，而编辑器可以直接和终端交互，仍然可能一直等着。这种情况靠每条命令的超时来结束，或者在命令环境里设 GIT_EDITOR=true，让 git 根本不开编辑器。

第 16 页

小模型最常见的失败：永远重复同一个调用

「相同」的定义：工具名加解析后的参数（parsed arguments）。

写入之后的重复是进展（progress）。

精确匹配会漏掉 L07 的第 8、9 步（Exact match）。

讲者备注：小模型最常见的失败就是永远重复同一个调用——读一个文件、不据此行动、再读一遍。「相同」需要定义：比较工具名和按键排序后的解析参数，而不是原始的 arguments 字符串（空白可能不同）。

再决定重复是否总是循环：修完后再跑 pytest 是工作顺利；中间什么都没写又跑一遍才是循环。以「调用加结果」为键，或者任何写入都重置计数，就能区分。还要注意精确匹配漏掉什么：L07 的第 8、9 步都删了任务列表，但并不相同——一个以 python -c 结尾，另一个以 python cli.py add 结尾。

第 17 页

连续计数，任何一次成功都清零

连续计数：任何一次成功都会重置（resets）。

没能运行：算一个错误（Could not run）。

运行了但以 1 退出：由你决定（exited 1）。

讲者备注：模型已经迷失、恢复不过来。错误就是结果（规格 2.1），所以每次都会告诉模型；连着几个可能是模型在自我纠正，连着很多就不是了。计数是连续的，任何成功都会清零。

什么算错误才是要做的决定：工具没能做到要求的事算——文件不存在、命令被超时杀掉、参数不是合法 JSON。运行了但以非零退出的命令就不那么清楚：pytest 以 1 退出是信息，把它算作错误，你就会在修测试修到一半时终止运行。下半场还会加一种情况：拒绝算不算错误。

讲者备注：所有退出走同一个地方。演示用的 agent 抛出一种携带原因的异常，由一个处理器写退出行并打印总结。另一种做法是五处 break 加一处 return，迟早有一处忘了记日志——而日志结尾没有退出行的那次运行，恰恰是你最想弄明白的。

六个是下限而不是全部清单：演示 agent 还有两个，因为总会发生规格没点名的事，日志仍需要一个词。truncated 是 length 的情况；endpoint_error 是 POST 本身失败——服务器挂了、流在中途断了（即 F1），或者周四 Toolkit 偶尔的 502。崩溃不是退出原因，它是一次没有退出行的运行。
