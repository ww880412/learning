模型看到的是什么？

模型看到的是 token，不是字符或单词

token 是模型在训练中见过的文本片段；字节对编码（BPE）反复合并最常见的相邻对，直到词表约 10 万个。

课件：没人挑选这四块，它们只是常见到足以占一个位置的片段。

S1 L02 slides「Real tokens, real IDs」，讲师备注
token 化让你付出什么？

token 既是花费单位，也是注意力单位

啰嗦的代码更贵：用厂商 API 花美元，在自己机器上花内存和秒数。

每个 token 都在争注意力；你的标识符被切成常见碎片，不会因为是你起的名字就更受重视。

  • 讲师备注：同一个函数，啰嗦写法贵 4 倍；不是「信息更多」，而是更贵、更分散注意力。
S1 L02 slides「What tokenization costs you」「9 tokens / ~35 tokens」，讲师备注
模型能看到什么？

窗口外的东西，模型一律看不到

上下文窗口（模型一次能看到的全部 token）里有文件、对话、repo map、系统提示词；窗口外什么都没有。

课件：这是工程师需要知道的关于 LLM 最重要的一个事实。

S1 L02 slides「What the model sees」
为什么花费比上下文涨得快？

上下文翻倍，计算量翻四倍

生成下一个 token 时，模型给窗口里每个已有 token 打权重，不只看附近的。

课件：窗口是预算，不是容器。讲师备注：文本多 32 倍，花费不是 32 倍，而是约 1000 倍。

  • 课件的图：在 import httpx … resp = httpx. 之后生成 get，模型最倚重 httpx 和点号，但每个 token 都打过分。
  • 讲师备注：这就是在笔记本上「把整个仓库贴进去」行不通的原因。
S1 L02 slides「Weighing the whole window」「Every token attends to every other」，讲师备注
/add main.py     # 文件进入上下文
/drop main.py    # 文件离开上下文
/tokens          # 看清窗口里到底有什么
/clear           # 清空对话（保留文件）
长会话为什么越聊越差？

对话越积越多，窗口里大半是死重

每轮你发的、它回的都留在窗口里；模型分不清现在为真的和第 3 条消息时为真的。

做法：换任务就 /clear。Claude Code（L05）会替你压缩，而压缩会丢信息。

  • 大上下文的三种代价：花费（注意力是平方级）、延迟（笔记本上首个 token 要等几十秒）、质量（大海捞针，更大可能更差）。
  • 课件：Aider 手动 /add 的麻烦不是缺陷，而是你本来就该有的纪律。
  • 课堂讨论题：长对话变差时，窗口里发生了什么？
S1 L02 slides「Three costs of large context」「Aider’s friction is the lesson」「Context drift」「Chat break」
幻觉到底是什么？

幻觉不是故障，是没有查证步骤的补全

模型自回归采样：从分布里挑最可能的下一个 token；没有核对事实、查数据库或「这个存在吗」的步骤。

上下文沉默时，统计先验胜出：项目用 httpx，提示词没提，模型就写 requests。

代码里的幻觉有哪几种？

模型需要事实时，就把事实给它看

课件列三种：编造 API、过时知识、签名写错；还有一种是上下文本身就没有答案。

最后一种模型会猜得很合理，你从输出上看不出来。

模型变强有几个方向？

能力和知识是两个轴，别混为一谈

课件：小而新的模型可以胜过大而旧的模型。讲师备注：两个轴搞混，就会选错模型。

前沿模型会替你兜底，4B 模型不会；两周内你会在 4b 和 9b 上跑同一个仓库，亲自感受差距。
