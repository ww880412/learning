这讲一句话讲什么？

Agent 的上下文不能太长，也不能太短

语言模型「活在当下」，只管现在的输入；Context Engineering 决定这次输入放什么。

本讲三段：Context Engineering、Agent 之间的互动、Agent 对学术研究的冲击。

# 没做 Context Engineering 的 Agent（影片 1 05:01）
C = []                        # 上下文
for t in 1 .. ∞:
    I_t = 现在发生的事      # 人的话或工具输出
    O_t = LLM(C + I_t)
    C = C + I_t + O_t          # 只增不减

# Context Engineering 改的就是最后一行
问题出在哪一行？

不做处理时，上下文每一步只增不减

讲者把 Agent 写成从 1 到无限大的 for 循环；每步把输入和输出接到上下文后面。

后面所有方法都在改写「上下文怎么更新」：压缩、过滤、交给语言模型自己管。

压缩有哪几种？

压缩有摘要、清除、卸载到文件三种

卸载把工具输出存进硬盘上的 log1.txt，上下文只留一句「详见 log1.txt」。

卸载的好处：语言模型真的需要时，还能用 Read 把原文读回来。

LLM 摘要多呼叫一个语言模型
Hard Clear（observation masking）直接换成一句占位
预期上下文变短，花的 token 一定变少
实际步骤不见了，Agent 重做做过的事（轨迹延长），总 token 没下降
哪种压缩更好？

简单的清除，常常和摘要表现差不多

讲者引用 arXiv 2508.21433 在 SWE-bench 上的比较：不压缩的 raw agent 多数表现不错，但耗更多 token。

论文发现 observation masking 的表现很多时候和 LLM 摘要差不多。

  • 论文对 LLM 摘要的解释：轨迹延长，Agent 不确定刚才执行过没有，于是重复执行，步骤反而变多（影片 1 11:00–12:00）。
  • 课件没有给具体数字，这里不写数字。

失败：摘要丢了关键信息怎么办？

ACON 用失败例子改写摘要指令

context collapse（压缩后原本能做的任务做不了）发生在摘要丢了最重要的信息时。

ACON 不训练模型，只让语言模型读失败例子，写出「摘要要保留什么」。

  • 例：反省后写出「保留凭证变数、token 状态、认证需求和受保护 API 的防护规则」（课件 p13）。
  • ACON 在 AppWorld 上做实验；讲者说「还真的有用」（影片 1 23:00）。
  • 也有论文微调专门做压缩的模型，例：SUPO 用任务的 reward 训练（课件 p15）。
  • 讲者把它连回上一讲的删邮件事件（影片 1 21:01）。

子代理和压缩什么关系？

子代理等于让 Agent 自主压缩

子代理执行 return 后，它做过的事从主上下文消失，只留 Return 内容。

讲者：模型不喜欢压缩（抹除记忆），也难靠 prompt 稳定使用压缩工具，这能力要另外训练。

  • AgentFold 让模型自己「折叠」步骤，需要微调模型（课件 p17）。
  • arXiv 2510.11967：主干上下文过长会被惩罚、子代理做超出范围的事也会被惩罚；讲者说光看答案对不对不够（课件 p20，影片 1 35:00）。
  • 论文例子：找一篇 2023 年论文时，主上下文随子代理伸长、缩短（影片 1 32:00–33:01）。

怎么不让无关内容进来？

过滤和按需加载在进入前就挡掉内容

OpenClaw 的 memory_get 可指定起始行和行数，只读需要的部分。

MCP-Zero 让 AI 先说出需要什么工具，再搜索加载；OpenClaw 的 SKILL 也是按需加载。

  • arXiv 2601.16746：读 log 时用小模型先滤掉和「bug fixing」无关的内容（课件 p22）。
  • 讲者：工具多了，模型会直接超过上下文窗口（影片 1 42:01）。

深入一层：能不能全交给语言模型？

Agentic CE 让语言模型自己改写上下文

每一步由语言模型把旧上下文、输入、输出写成下一步的上下文。

Dynamic Cheatsheet 的核心：只存未来用得上的东西，例：有效策略、可重用的 code、关键发现。

  • ACE（arXiv 2510.04618）用 Generator、Reflector、Curator 三个角色更新 Playbook（课件 p30）。
  • Recursive Language Models（arXiv 2512.24601）把大部分上下文放硬盘，让语言模型写程序去搜（课件 p31）。
  • 课件最后一页用问句收尾：「把一切交给 LLM？」，没有给结论（课件 p33）。

AI 写论文到什么程度了？

好论文仍要人决定点子和实验设计

Agents4Science 要求 AI 当第一作者、AI 审稿，最后由人类给评价。

被接受的论文，人类在点子发想和实验设计上介入更多；数据分析和写作 AI 看起来能独立完成。

  • AI 的角色：工具（一个口令一个动作）→ 协作 → 代理（自己完成任务）；今天通常要人来决定做什么（课件 p48、p58）。
  • 例：Andrew Hall 用 Claude Code 重跑旧分析，写了「100 倍研究机构」（课件 p49–50）。
  • AAAI 2026 让 AI 进入审查流程，只给意见不打分（课件 p54）。
  • 课件结论：在 Agent 萌芽的时代，「想做」什么比「会做」什么更重要（p59）。
