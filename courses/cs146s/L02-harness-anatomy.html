这讲一句话讲什么？

循环没变，变的是包在外面的 Harness

Harness（包在模型外面、负责循环和注入内容的程序）里有 8 个组件：系统提示词、配置文件、工具列表、Plan 模式、子智能体、Skill、Hook、压缩。

课件：Harness 设计是编码智能体最重要的问题之一。

  • 讲师说：除了模型，Harness 的一切都能看见；模型是放在服务器上的私有参数。
  • 本讲拆的是 Claude Code 搭配 Opus 5.5 的 Harness，讲师说这个版本当时刚发布两天。
  • 讲师说：这些原则不只用于编码，也适用于销售、法律、客服等领域的智能体。

模型怎么知道有哪些工具？

工具的名字、描述和签名都进提示词

工具列表是一个列表，每项是一个字典；每次请求都完整附带一遍。

所以写工具时，docstring 和参数类型要清楚一致；模型靠它们判断何时用这个工具。

  • Claude Code 约有 40 个内置工具：读写文件、Bash、定时任务、网页搜索、LSP 搜索、子智能体、计划、创建 artifact、列 MCP 资源、调用 Skill、向用户提问、推送通知。
  • 讲师认为模型经过后训练，专门优化过使用这些内置工具。
  • 每个已加载的 MCP 服务器（包括第三方）的工具，也都在这个块里。
  • 字段名 input_schema 是补充：讲课只说「有一个 schema，相当于函数签名」。

系统提示词是谁写的？

系统提示词由 Harness 写死，你控制不了

它是模型行为的蓝图：定义 Harness 的行为、护栏和环境；每次请求都带上。

讲师说：Opus 5.5 版约 50–80 行，前一两个月还是 200–250 行，删掉了 Git 用法这类说明。

  • 讲师推测：这些知识已经通过训练进入模型参数，不用再写进提示词。
  • 讲师说：第一个请求发出前，可能已经有上万 token 被你控制不了的内容占用。
  • 记忆块：Claude Code 有一个从你的行为中学习的记忆机制，提示词规定记忆存放的路径和写入格式。讲师认为路径是按项目区分的。
  • 讲师认为看到系统提示词不算大的攻击面：截请求有开源工具，Codex 的 Harness 本身就在 GitHub 上。

你能控制哪部分提示词？

CLAUDE.md 是你能控制的那份提示词

Harness 把 CLAUDE.md 的内容放进第一个 user 块，前面写明这些指令覆盖默认行为、必须照做。

写太多会过度约束模型，讲师比作「对你的指令过拟合」。

  • CLAUDE.md 是 Claude 专用名，AGENTS.md 是更通用的标准；两者作用相同，可以用符号链接把 CLAUDE.md 指向 AGENTS.md。
  • 演示项目的 CLAUDE.md 由讲师和 Claude 一起写，内容是项目结构的高层描述。
  • 怎样写好这类文件，课程后面有一整讲（第 4 周：CLAUDE.md、AGENTS.md、Hook）。

Plan 模式到底是什么？

Plan 模式就是一段注入的提示词

进入 Plan 模式的工具被调用后，Harness 注入一段规定计划流程的文字；做完再用另一个工具退出。

关键产物是最后的 plan 文件。

  • 讲师的演示：给待办工具加周期提醒，例如「每周给植物浇水」。进入 Plan 模式，和模型来回讨论后产出计划。
  • Plan 模式可以继续向用户提问，澄清需求和架构。
  • 讲师说大约九个月前，大多数编码 Harness 都加了 Plan 模式，Codex 也有。
  • 进入和退出工具的确切名字，讲师没记清，未确认。
S1 课件「Plan Mode」；S2 讲课实录 48:03–51:14
MCP 工具最小的原语，像一次 API 调用：一个输入、一个输出。
Skill写好的流程：多个工具调用、脚本，中间用提示词串起来。
MCP 工具怎么进上下文全部定义，每次请求都带。
Skill 怎么进上下文先只放元数据；相关时再拉入 SKILL.md 全文。
Skill 和 MCP 工具有什么不同？

Skill 用到时才进上下文，MCP 每次都进

讲师说：引入 Skill 的一个原因是渐进披露（相关时才把信息放进上下文）。

演示：讲师说「Check my code quality. Use the skill.」，Harness 注入命令消息，再把 SKILL.md 内容放进上下文。

  • Skill 可以由模型按上下文主动调用，也可以由用户明确调用。
  • 讲师为课程写了一个 check code quality Skill，内容是好代码和坏代码的区别。
  • 课程第 3 周有一整讲讲 Skill 设计。

子智能体省了什么？

子智能体的探索不留在主对话列表里

主智能体用一个工具调用启动子智能体；子智能体用全新上下文工作，做完把结果交回。

课件：可以并行，但 token 花费会上升。

  • 讲师在演示里调用过一次子智能体，大概是检查性能，他记不清了。
  • Hook：在 Harness 生命周期的不同点插入的提示词或代码，适合做前处理、后处理。本讲只提了一句，最佳实践留到后面。

上下文快满了怎么办？

压缩用一份摘要替换整段对话列表

压缩有两种触发：快超出上下文窗口时自动触发，或你手动触发；一段专门的提示词规定怎样写摘要。

课件：压缩会丢信息，所以你可能要改写自己的版本。

一句提示词发出前，Harness 先拼好五层内容

Harness 会在哪里出问题？

三种失败都来自塞进上下文的东西太多

讲师说：有研究在测 token 多到什么程度时表现开始下降；他把这个区域非正式地叫作 dumb zone。

课件原则：Mind the context window，避开 dumb zone，小心工具膨胀。

为什么 Harness 越做越简单？

Harness 越来越依赖模型本身的能力

讲师说：Claude Code 约 40 个内置工具，比过去的版本少；业界趋势是用更少、更强的工具，例如 Bash、SQL。

讲师说：投入模型还是投入 Harness，业界一直来回摇摆；现在倾向让 Harness 尽量简单。

  • 讲师说：Claude Code 大约在去年 12 月走红，一个原因是 Harness 极简，工具少但几乎什么都能做。
  • Bash 让模型通过文件系统和命令行完成复杂操作，讲师说它本身就是一门完整的语言。
  • 课件原则：提示词的内容和长度会变，所以要让它们容易调整。
