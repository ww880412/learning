CS146S 第 1 讲 · 用 200 行代码写一个 Claude Code
这一讲讲什么？

编程智能体 = 两层循环 + 一个对话列表

外层循环读你的一句话。内层循环反复问模型、执行工具，直到模型不再要工具。

所有状态只存在一个地方：conversation 列表（对话列表）。

课件把步骤写成 4 步：读终端输入并追加进对话；告诉模型有哪些工具；模型在合适时请求工具；程序在模型外执行工具并返回结果。课件列的工具名是 Read_file、List_dir、Edit_file；官方代码里叫 read_file、list_files、edit_file。

官方实现约 200 行 Python，只有 3 个工具：read_file、list_files、edit_file。课件标题就是「How to Build Claude Code in 200 Lines of Code」。

为什么需要循环？

模型碰不到你的电脑，客户端替它动手

模型只把文字变成文字。它不能打开文件。

客户端在模型外（off-LLM）执行工具，再把结果写回对话。

课件原话：用户和客户端（Windsurf、Cursor、Claude Code）交互，客户端和底层大模型跑一个循环。大模型有时发出工具调用，由客户端在模型外执行。

所以「模型调用工具」这个说法不准确：模型只请求，程序才执行。

模型怎么知道有哪些工具？

工具说明写进系统提示词，模型只能靠读它

程序用 inspect 取出每个函数的 docstring 和参数签名，拼进提示词。

提示词规定回复格式：只回一行 tool: 名字(JSON)。

  • 这条提示词放在对话列表第 0 条，角色是 developer（:148–151）。
  • docstring 写错，模型就会用错工具。函数注释在这里就是给模型看的说明书。
  • {{JSON_ARGS}} 的双括号是 Python format 的转义，模型实际看到 {JSON_ARGS}。

def extract_tool_invocations(text):
    invocations = []
    for raw_line in text.splitlines():
        line = raw_line.strip()
        if not line.startswith("tool:"): continue        try:
            after = line[len("tool:"):].strip()
            name, rest = after.split("(", 1)            args, _ = json.JSONDecoder().raw_decode(rest)            invocations.append((name.strip(), args))
        except Exception:
            continue   # 格式坏了：静默跳过
    return invocations
程序怎么从文字里认出工具调用？

逐行找 tool: 开头，切出名字，再解析 JSON

例：tool: read_file({"filename":"hello.py"}) → 名字 read_file，参数是一个字典。

解析失败的行被静默跳过，不报错。

  • raw_decode 只解析开头的一个 JSON 对象，返回对象和结束位置。所以结尾的 ) 不影响解析。
  • 一次回复可以有多行 tool:，每一行都会被执行（:176 的 for 循环）。
  • 返回空列表 = 没有工具调用 = 内层循环结束。这就是循环的停止条件。

循环到底怎么转？

内层循环不停，直到模型的回复里没有工具调用

每次问模型，都把整个对话列表发过去。

工具结果用 user 角色追加，内容包在 tool_result(...) 里。

  • 为什么用 user 角色：本课不用 API 自带的工具调用功能，结果只能伪装成一条普通消息。系统提示词告诉模型：看到 tool_result(...) 就继续任务。
  • 内层循环没有轮数上限。模型一直要工具，程序就一直跑（补充：代码里没有上限）。

一次真实运行里，列表怎么变？

一句任务，对话列表从 1 条长到 7 条

第 2、4 条是模型请求，第 3、5 条是工具结果。第 6 条没有 tool:，内层循环 break。

注意参数名：read_file 用 filename，另外两个用 path。

返回值格式和代码一致：read_file 返回 file_path + content（:44–47），edit_file 返回 path + action（:91–94）。

路径 /work 和模型的回复文字是示例数据，用来演示格式。

深入一层：代价在哪里？

每多一步，下一次调用就要重发更多文字

模型没有记忆，对话列表就是它的全部记忆。

读过的文件越多，每次调用就越长。

本课代码不做任何裁剪：列表只追加，不删除。课件的总结写「Good context leads to good code」。第 1 周作业要你观察真实产品在对话变长后，请求内容怎么变化。这是后面讲上下文工程的起点。

哪些情况会出错？

只有一种错误回到了模型，其余会崩溃或被吞掉

错误写回对话，模型才能修正。

抛出的异常不会进入对话，程序直接退出。

改进方向（补充）：在执行工具外包一层 try，把异常文字写成 tool_result；工具名不存在时也返回错误说明；解析失败时告诉模型格式错了。这样每一种失败都变成模型能读到的信息。
