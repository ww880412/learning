CS329A 第 9 讲（课表第 20 讲）：未来研究方向——多样性、自我验证、自出题与每瓦智能

最后一讲先回顾整门课：推理时扩展、训练时扩展、由验证器驱动的自我改进循环、用工具的端到端 agent。然后讲三个卡住自我改进的地方和对应的论文：模型自己生成的数据不够多样（多 agent 微调）；只看最终答案无法保证推理正确（DeepSeekMath-V2 的验证器加元验证器）；训练用的题要靠人挑（Absolute Zero 让模型自己出题、自己解）。后半段讲效率：本地小模型已能答对大部分聊天类查询，用「每瓦智能」衡量，云端和本地的混合推理可能是下一步。本页依据官网课表与录像英文字幕（约 67 分钟）。

口述 00:05–03:02：回顾：从 LLM 概览出发，讲了推理时扩展和训练时扩展这类自我改进技术，其基本循环由验证器、运行验证器得到的反馈和奖励驱动，再用强化学习乃至搜索算法（讲过 AlphaEvolve 等）。然后转到用工具搭建端到端 agent 工作流，多步任务需要查知识库等，涉及机器人、推理等领域。Azalia 补充，一位客座讲者讲了符号方法，属于工具使用，也能用于合成数据。

口述 03:02–05:00：当前 LLM 单靠自己还不足以推进到完整目标，常常要手写工作流来编排 LLM 和工具，但编码 agent 等场景里已能看到自己驱动的 agent 工作流；还要能在走错时自我纠正、不断提升，这就是自我改进。本讲按论文的关键思想讲未来方向，兼顾自我改进和智能的效率。

原文 官方课表 · 讲者口述
口述 05:00–34:00

生成的数据要多样、推理过程要可验证、训练用题要能自己产生

口述 05:00–07:00：推理时扩展靠多采样、多数投票，训练时扩展把反馈和奖励接进循环，但仍局限在数学、编码这类窄领域。三个问题：怎样跨领域泛化、让推理链更多样；怎样验证推理过程；训练用的提示目前是静态选的、要人挑，怎样突破数据瓶颈，让自我改进循环自己挑数据。

口述 07:00–09:03：第一篇（多 agent 微调）的出发点：预训练是对互联网数据的压缩，指令微调要真人偏好数据；替代办法是用 LLM 自己生成的数据，但自我改进几轮到几十轮就停了，根本原因是缺乏多样性——人类数据跨越漫长时间，非常多样，单个模型对一批提示生成的输出则不然。

口述 09:03–13:04：做法是分工：生成 agent 产出多样的初始解，批评 agent 评估和改进，都是专门化的。多轮辩论：各生成 agent 给出答案，汇总或拼接所有回答，批评后加入输入，再生成更新的答案，多数投票后再汇总，可以持续多轮。和单 agent 自我批评的区别是在生成阶段就有多样性。讲者说最简单的版本是直接用不同模型、不同提示。这些轨迹用来微调各个 agent。

口述 13:04–15:03：在两个开源模型上，多 agent 微调能持续提升性能，Llama 反应更明显；更有意思的是回答在这个过程中一直保持多样。这是稍早的工作，数字不算高，但在 GSM 8-k 这类相邻领域，微调后的 agent 也更好，说明能泛化到训练领域之外。

口述 15:03–18:01：第二个问题是验证。数学题或定理证明通常看最终结果，用结果奖励模型比对标准答案，这已让 AIME（字幕作 Amy）等基准饱和；但答案对不代表推理对，定理证明需要严格的逐步推导。DeepSeekMath-V2 不只训练奖励模型，而是训练验证器：先让人在没有参考解的情况下找出证明里的问题，据此训练 LLM 找出问题并改进。

口述 18:01–20:02：它再加了元验证器：审查验证器的分析是否合理——验证器（这里是 LLM 评委）可能编造不存在的错误，元验证器检查这些问题是否真的存在、分数是否和问题对得上。验证器按 0、0.5、1 给证明打分，再用来改进生成器，生成器产出更难的证明。

口述 20:02–23:01：它基于 DeepSeek-V3 系列模型，只靠验证–生成的迭代优化，就在 IMO 和 CNML 题上取得很好的成绩；用 best@32（32 个证明里挑最好的）时，在 2024 年 IMO shortlist 上证明得分接近 42%（Gemini 版本由一位客座讲者介绍过），而这是开源的。结论：最好的证明得到更高的验证分，生成器学会区分高质量和有缺陷的证明；元验证减少验证器幻觉出的问题，再加上激励生成器通过深思熟虑的推理提高质量。讲者说这开始打破验证瓶颈。

口述 23:01–27:02：第三个问题是训练用什么题。传统上要专家造题答对（数学要数学专家、IMO 要 IMO 专家、编码要强程序员），模型超过人类后，找专家越来越难。Absolute Zero 让模型自己提出任务、自己求解，在编码领域可行，构造三类任务：演绎（给程序和输入，环境执行得输出）、溯因（同样生成程序和输入、环境算输出，任务是反推）、归纳（取已有程序，生成新输入和自然语言描述）。

口述 27:02–30:02：出题者的奖励按难度优化：解题者成功率为零得 0 分，非零则得 1 减平均成功率，所以要挑当前模型能部分解出的题；模型变强后出更难的题。生成的任务要验证有效：执行程序看有没有错误、做安全检查等，并用一个缓冲区记录过往任务和成功失败次数，形成随时间演化的课程学习。在编码基准上，不用多少人工数据也能爬坡。

口述 30:02–33:00：涌现行为：程序复杂度随时间上升，程序和答案的多样性在循环设置正确时也在提升，出题越来越难。虽然只在自己出的代码题上训练，在编码和数学基准上都表现很强，这一点令人意外。这和 SWiRL 的观察一致：在多跳检索问答上生成合成数据做 RL，模型在调用 Python 解数学题等其他工具调用上也变好。

口述 33:00–35:01：小结：要真正泛化和推理，推理链需要多样性；需要验证推理过程；需要模型自己产生训练数据和课程。Azalia 补充一个研究问题：只用可验证领域、生成多样的可验证合成数据再喂回模型，自我改进的前沿能推多远——这是很耗算力的实验。

口述 35:01–40:03

验证太慢时，训练一个奖励模型来预测结果

口述 35:01–37:04：有人问不属于可验证问题的应用怎么办。Azalia 说有些领域验证很慢，比如科学发现、芯片设计里很慢的仿真；RL 训练要几百上千步迭代，验证器得几乎即时，最多等几分钟、一小时，等不了几天或人工给奖励。

口述 37:04–40:03：线上学生问芯片设计这类难验证的领域怎么办：一个办法是训练单独的奖励模型来预测仿真结果，作为 RL 回路中的验证对象，但其通用性取决于数据量，不准时会出问题。Aakanksha 补充：模型也许能优化简单的内核，但把所有东西拼起来做性能分析、改未优化的部分就难得多，通常会把问题拆开。

口述 40:03–59:03

本地小模型已能答对大部分聊天类查询；能源会成为最宝贵的资源

口述 40:03–42:03：自我改进意味着更多推理，智能是有成本的。Azalia 讲她们最近的工作：AI 推理的负载会是什么样，需要多大的模型和什么样的加速器。现在是「大型机时代」：ChatGPT、Gemini 这些大模型都跑在云上。

口述 42:03–44:00：需求爆炸：Google Cloud 过去 20 个月的算力服务增长了约 1200x，NVIDIA 同比增长 10x，都由 AI 驱动；要满足需求大约需要 250 吉瓦的数据中心。Google 处理的 token 数，去年二月是 160 trillion，今年十月字幕作 1.3 billion（单位显然有误，应更大，未确认）。这是历史上增长最快的算力需求之一。他们分析了一个很大的 ChatGPT 用户数据集，约 77% 的请求是实用指导、信息查询这类任务。

口述 44:00–47:05：用户问的问题会随聊天机器人变强而越来越复杂，但绝大多数查询仍是相对简单的。另一方面，从 2012 年至今，本地加速器的 GPU 内存提升了约 126x，现在 MacBook 能有约 100 GB 内存，量化后能装下很大的模型。可现在几乎所有流量都去了云端的 H100、TPU、GB200 和 GB300（字幕作 GP200、GP300）。

口述 47:05–49:01：她们定义了「每瓦智能」（IPW）：平均任务准确率除以功耗。本地模型在研究里指活跃参数不超过 20 billion 的模型（如 Gemma3 等），硬件包括企业级和本地加速器；负载有来自 ChatGPT 等的 1 million 个查询，以及 Natural Reasoning、MMLU-Pro（字幕作 MLU pro）、SuperGPQA 等推理基准；指标有准确率、能耗、延迟、算力等。

口述 49:01–52:04：本地模型的进步很快：2023 年以来能解决的聊天查询比例提高了 3.1x，只用了两年，现在能处理约 88.7% 的这类查询。本地加速器的效率落后于企业芯片，比如 Apple M4 Max 的每瓦智能比企业芯片低约 1.5 倍（口述「1 and 1/2x」）。同样的模型在 B200 上的每瓦智能比在 Apple M4 上高，因为 B200 专为语言模型负载优化，而设计 M4 时没有预期 LLM 会在本地运行。这项指标两年里提升约 5.3x，其中 3.1x 来自更好的模型，1.7x 来自硬件改进。本地模型越来越强，模型和硬件效率也在提升，这意味着方向在变。

口述 52:04–55:02：开放的研究方向：推理时扩展和合成数据新时代的基础原理——反复问同一个问题时，正确答案是怎样出来的；怎样把成功轨迹蒸馏回模型；从合成数据飞轮自然过渡到持续学习：人边经历边学，模型则隔一段时间才微调，这种不匹配也许能由持续学习解决。

口述 55:02–59:03：低延迟的推理时扩展：重复采样、反复修改、工具调用与主流单轮聊天很不同，需要为它优化系统和算力。这门课讲预训练较少（尽管 Aakanksha 是预训练专家），主要讲后训练和推理时扩展。从云端到本地的可能转变也提示了混合推理服务引擎：按需要和复杂度在本地与云端之间平滑分流。能源会是今后最宝贵的资源，每瓦智能这类指标和对能耗的优化会越来越重要。

口述 59:03–67:00

持续学习不一定靠微调；为 agent 自动造环境在有限空间里容易

口述 59:03–63:03：学生问持续学习更关乎记忆系统还是模型本身。Aakanksha 说即使在多步推理里，从成败中学习、把技能保存进权重或部分权重、学会学习，都是我们现在还没有的能力。Azalia 说可以设想无限长、能完美访问的上下文，把正负经验都放进去，也许就是一种持续学习；即不微调、而是把经验放进激活或 KV 缓存的上下文学习。

口述 63:03–66:03：如果是知识库，更新数据库最简单；但真正想教 LLM 的是对新信息推理的能力，那是技能迁移问题。另有学生问 Absolute Zero 之外有没有 agent 自己造环境的论文：讲者说在游戏这类有限空间里用代码建模拟很直接，难的是它能否代表真实世界的反馈。

口述 66:03–67:00：结语：这是一个快速演进的领域，今天教的到下次开课时就会成为历史，但基础技术长期有价值，新东西仍建立在它们之上。讲者感谢大家，希望这只是大家做研究和项目的开始。
