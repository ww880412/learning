CS329A 第 1 讲：课程概览——从规模定律到会自我改进的 agent

开课第一讲分三段：先回顾大模型这五年怎么变强（规模定律、few-shot、思维链涌现、指令微调与 RLHF），再讲 2024 年起的新方向——推理时多花算力（Large Language Monkeys 的重复采样）和会「想」的推理模型，最后说明为什么要学 agent：从单轮聊天到能定目标、调工具、自己判断何时停的工作流，并交代作业、项目和成绩安排。本页依据官网课表与 Stanford Online 录像的英文字幕（约 69 分钟）。

口述 02:00–11:03

模型越大越好：损失随算力、数据、参数下降，还会突然长出新能力

口述 02:00–04:04：GPT-3 以后最让人震惊的是「参数越多越好」。讲者用三张规模定律图说明：横轴分别是算力、数据集大小、参数量，纵轴的测试损失都随之下降；这是 GPT-3、ChatGPT、PaLM、Gemini 这一路模型的基础。但讲者也说，这条路到去年开始出现某种饱和。

口述 04:04–05:01：2018 到 2024 年模型规模几乎一路上涨：Bert 是 340 million 参数，GPT 2 是 1.5 billion，GPT 3 是 175 billion，PaLM 是 540 billion，GPT-4 估计达到数万亿（trillions）参数——「大」语言模型的「大」就指这个。

口述 05:01–07:01：变大带来三件事：各类基准持续提升；学会 few-shot（给几个例子就能照着做，不必为每个领域单独微调，原型变得很容易）；以及涌现行为，有些能力只在大模型里出现。GPT 3、PaLM 等模型带来了这种能力。讲者用「把英语翻成法语，再翻 cheese」解释 zero-shot（只给任务说明）和 few-shot（再加几个示例）。

口述 07:01–09:01：最重要的涌现行为之一是思维链（chain of thought）。普通提示只给一道例题和答案；思维链提示还写出推理过程。例子是 Roger 有 5 个网球，又买了 2 罐、每罐 3 个，不只回答 11，而是写「2 罐乘 3 个是 6，5 加 6 是 11」。讲者说这么简单的题如今 1B 参数的模型都能做，但思维链这个性质至今仍然成立。

口述 09:01–11:03：思维链对推理模型和过去一年的进展非常重要，而且也是规模大了才有：LaMDA、GPT、PaLM 在数学数据集上的结果显示，LaMDA 约 8 billion、GPT 约 7 billion 的小模型用思维链几乎没帮助，模型变大后才能利用上下文里的推理过程。模算术、单词还原等任务也是到某个规模突然会做。所以前沿实验室仍在推规模定律，期待更多涌现行为。

口述 10:03–20:03

ChatGPT 的跃升不只靠变大，还靠指令微调和 RLHF

口述 10:03–12:01：ChatGPT 于 November 2022 发布，达到一百万用户（one million users）只用了 five days，远快于其他知名软件和服务。讲者强调，它相对 GPT-3 的跃升除了参数规模，还有两块关键创新：指令微调（讲者口误说成 instruction tooling）和基于人类反馈的强化学习（RLHF）。

口述 12:01–15:02：训练流程先是预训练（预测下一个 token，最简单的一步），再是微调。预训练完的模型「什么都见过」，却不会按指令做事，所以要做对齐：让模型遵循人的目标、偏好和价值。讲者说这仍是大问题、远未解决。第一步微调仍是下一个 token 预测，但换成质量高得多、精心整理的数据（书籍、创意文章等，公司会为此花上百万甚至上亿美元）。

口述 15:02–17:01：第二步是指令微调：用「指令 + 问答对」的数据（过去两年多是人写数据、角色模板和合成数据的混合）教模型理解问题、按步骤给出答案，比如「请回答：水的沸点是多少」。数据集的质量和覆盖面对这一阶段的模型质量影响很大。

口述 17:01–20:03：第三步 RLHF 的区别在于目标和数据的构造：不再是监督的「提示 + 标签」，而是让人（有时是专家）给模型的回答打分、比较好坏，据此训练一个奖励模型，再让模型的生成去迎合这个奖励模型。奖励可以按正确性、有用性、具体程度、无害性等来定义。讲者总结：指令微调和 RLHF 是 ChatGPT 胜过 GPT-3 等早期大模型的核心；而从大约一年半前起，推理阶段也成了让模型更强的新前沿。

口述 20:03–28:06

同一个模型多采样几次、再用验证器挑，弱模型也能超过强模型

口述 20:03–22:00：Azalia 介绍她们去年夏天的工作 Large Language Monkeys，名字来自「无限猴子定理」（猴子一直敲打字机，终会敲出莎士比亚全集；讲者说明这个说法并非证明）。做法是重复采样：同一道题让模型并行生成很多次，再用验证器或选择机制挑出正确的作为系统输出；验证器可以理解为单元测试之类。

口述 22:00–24:00：可以用 temperature 让模型的回答更多样。在数学和代码基准上，把每题采样数从 1 增加到 10,000，看「至少有一个样本答对」的题目比例（coverage）。几个小一些的开源模型单次采样不如 GPT-4o，但多采样后全都超过了 GPT-4o。讲者的解读是：模型知道的远比问一次能得到的多；而且这叫推理时扩展，是因为完全没动模型参数。

口述 24:00–27:02：有些题在 10,000 个解里可能只有三四个是对的，说明扩展推理多么重要。学生问这和穷举答案有何不同：讲者答，答案空间极大，随机搜索不可能撞上，而让模型生成是很省样本的办法，10,000 并不多，有些还是 IMO 级难题，很小的模型也能解出。问到和 GPT-4o 比延迟如何：并行采样可以同时跑，延迟不是大问题，但算力成本有取舍，取决于题目类型和难度，后面的讲次会细讲。

口述 26:00–28:06：问到没有验证器的领域怎么办：有验证器时容易得多；没有时有一整套研究在训练 LLM 当评委（LLM as Judge）、LLM 奖励函数、带工具的 LLM，课上有一讲专讲验证器。问到温度能否无限调高：不行，太高会生成乱码，讲者说一般超过 1.2 左右效果就不好，但还有别的办法增加回答的多样性。

口述 28:06–41:01

推理时生成的大量合成数据回头用来训练模型，这就是这门课说的「自我改进」

口述 28:06–31:03：讲者回顾 DeepSeek（December 2024 发布）和 o1 系列、Gemini thinking 的核心创新：把微调和测试时扩展结合起来。测试时扩展成了生成合成数据的引擎——数学题知道标准答案，可以让模型生成通向答案的多种解法；代码题也能生成大量高质量数据——再拿来微调模型。讲者说这件事没有边界、非常值得研究，也是这门课最关心的「自我改进」。

口述 30:01–32:00：Large Language Monkeys 展示的是有验证器时 coverage 随样本数呈对数线性增长；OpenAI 去年 9 月发布 o1 时展示的是 pass@1：在很难的 AIME 数学题上，测试时算力（对数刻度）增加，准确率上升。以前这种规律只在训练中看到，现在不改参数量的测试时也成立。动机和人一样：难题就多想、多试几种策略。

口述 32:00–35:02：推理模型解题的几个步骤：分析问题；拆解任务；自我演化（试一下、看反馈，比如跑测试、用计算器、自己评判）；自我纠错；换方案、回溯。讲者认为这些技能一部分来自人整理的训练数据，大部分是在微调和用合成数据做 RL 时学到的。例子是 o1 写一个转置矩阵的 bash 脚本：先像人一样梳理输入输出格式，再拆成解析输入、建二维数组等步骤，中途还会说「等等，这里可能不对」再改。和思维链提示的区别是：这次思维链由模型自己产生。

口述 34:02–36:01：o1 这类推理模型和非推理的 GPT-4o 相比，在数学计算、数据分析、编程等推理任务上更好，但个人写作、文本编辑不一定更好。

口述 35:02–38:01：学生问收益来自「真的写出推理过程」还是「只是被要求去想」。讲者答：训练数据把模型变成了通用的思考者，拆题、回溯、分析这些技能会迁移；也可以对照重复采样理解，基础模型多采样能提高 coverage（pass@k），推理训练提高的是 pass@1。推理过程虽然生成代价高，但能带来更好的答案，所以仍然要它生成。

口述 37:01–40:00：能否让小模型只负责总结答案？讲者说至少目前，模型更「喜欢」自己的推理轨迹，即使别的轨迹来自更好的模型；后面会讲 SWiRL 这类多步推理工作，以及让另一个模型来评估、给反馈。推理怎么教会的：两者都有——基础模型本身就有一定思考能力，指令微调数据里的思维链和模板示范了怎么想，课程还会讲结果奖励模型（outcome reward model）和过程奖励模型（process reward model）；模型的泛化已远超训练用的数据和指令。

口述 40:00–41:01：采样数能否随题目难度变化？讲者说据她所知没有已发表的工作直接这么做，后续工作用奖励模型来引导更多采样，这是值得探索的方向。

口述 41:01–52:00

agent 和聊天机器人的区别：有目标、会行动、看反馈、自己决定何时停

口述 41:01–43:00：聊天机器人和推理模型基本仍是单轮或聊天形式，不替你完成任务。今年、尤其最近几个月，Claude Code、Deep Research 这类 agent 让人能跑真实的端到端工作流，比如研究「来斯坦福上课该在哪里租一年房」，或在 Codex、Claude Code 里用英文指令改文件、找测试用例。所谓从 LLM 到 agent：给定目标后，模型规划步骤、与环境交互、根据反馈纠正，直到完成或回来说做不到。

口述 43:00–45:03：有目标、采取行动、决定何时停，这是 agent 与聊天机器人的区别；还可能要调外部工具、要有记忆来跟踪任务。目前简单场景（如深度研究）能端到端完成，但多数场景仍是静态的 agentic workflow：一个模型出方案、另一个评估是否接受；或像深度研究那样把多个输入分别交给 LLM 再汇总。开放问题上，按人的做法手工搭图、再用 LLM 评估器给反馈，比完全开放的循环更容易。

口述 45:03–48:02：工作流的部件有 LLM 调用、验证器（会有一整讲）、评委（LLM as a judge）、工具调用（深度研究要搜网页、查天气等）。编排方式有：提示链（像推理模型那样把任务拆开串起来）、路由（复杂任务走复杂流程，简单的走简单流程）、并行（深度研究同时查多个关键词再汇总，或拆成独立子任务再合并）、编排者（一个中心 LLM 做规划，Claude Code 里能看到先出计划）。数学、代码等可验证领域里，跑单元测试这类验证器能把反馈交回模型纠错。所以 LLM 要更会规划、更会多步推理、更会自我改进。

口述 48:02–50:05：编码 agent 的例子：LLM 通过终端与电脑交互，接到「实现一个测试」这类指令后，浏览仓库、搜文件、查看和编辑行、执行命令，再根据输出决定下一步改哪个文件。学生问为什么现在变得可靠了：讲者认为架构没大变，主要是模型更强、RL 更好——基于可验证奖励的 RL 和训练时扩展有效；模型变好后自我改进的循环就转起来了，比如 CodeMonkeys（去年课上讲过）里让模型给自己的代码生成单元测试来验证。

口述 50:05–52:00：讲者把这概括为「生成–验证差距」（generator verifier gap）：模型很容易生成大量内容，但有没有用需要反馈；创意写作这类领域人的反馈成了瓶颈，能做验证的领域才能持续改进模型，而稳健的验证很难，Azalia 会讲她实验室组合多个验证器的工作。验证仍是这个领域的瓶颈之一。

口述 51:01–53:01：学生问为什么反馈信号能带来这么大的跃升。讲者说这仍是开放问题：是 RL 还是预训练数据的多样性在起作用，没有共识，两者都有帮助；如果预训练模型多次采样至少能做对一次，反馈应能提高 pass@1，但为何跳得这么多还没完全弄清，现在只是「初露端倪」并开始商业化，也有迹象表明继续做 RL 会继续变好。

口述 52:00–58:02

编码、客服、深度研究、AI 科学家：重复性高、能验证的任务先被交给 agent

口述 53:01–55:01：编码 agent 拿到目标后，要先澄清用户意图，再去找相关文件，采取行动后通常需要某种验证，比如跑通测试，甚至自己生成需要通过的测试。最有用的是重复性任务：代码迁移、版本升级、重构代码库、数据抽取清洗、数据仓库迁移、写单元测试。

口述 55:01–56:01：客服场景：知识助手（客服不必什么都知道，问 LLM 并给出相关文章，比单纯建索引搜索好）、聊天里的智能回复、通话摘要等。

口述 56:01–58:02：深度研究：以前写综合报告要自己做文献综述、逐篇总结再综合，现在交给 LLM，读的文章可能比你还多；比如给它「2022 年冬奥会开幕式」，它会先找参考资料再搭提纲。AI 科学家（The AI Scientist 论文）把 LLM 用在出点子、迭代实验、写论文几个阶段；讲者说这些模型虽然会幻觉，但能提出大量不同的想法。

口述 58:02–69:01

三次作业 + 研究型项目：要有假设和实验，不只是做个应用

口述 58:02–61:02：学生问推理和思维链是训练出来的还是意外发现的。讲者答：思维链最初是被发现的涌现行为（解释过程模型就做得更好，讲者提到 GSM 8-K 上的论文最先展示这一点），模型读过全网数据，见过有条理的内容；而如今的推理模型是专门训练来思考的，并会学会何时需要多想、何时不需要；回溯、自我纠错等能力既可称涌现，也可说是在微调中被强化的，很难截然分开。

口述 61:02–62:01：课程由讲课和客座讲座组成，客座讲者来自前沿 AI 实验室，主题从后训练的演变到机器人里的多模态 agent，也有学生的项目展示。最新通知以 Canvas 为准。

口述 62:01–66:03：这一季有三次作业（比上次多一次，由助教新设计），外加课程项目。项目可 2–4 人组队（老师建议组队，额度合起来能多跑实验），课程提供 API 额度。可接受的项目例子：新的评测数据集或基准、研究已有 agent 系统的可靠性、在已有基准上用自己的想法爬分；希望学生读过课上的论文。老师强调要「研究型」：有假设、有要回答的问题和要看的改进，不能只是拼个应用演示（讲者原话是要多于 vibe coding）。要尽早开始，按时提交项目提案。

口述 66:03–68:01：期中项目展示要有实际进展，不能只是提案；期末报告权重很大；独立研究的工作可以用，只要不是照搬已有成果。上次开课有学生把项目发成了论文。成绩一半（50%）来自三次作业，另一半（50%）来自项目。海报展示定在 December 12，4:00 到 6:00 PM，会有业界的人来。

口述 68:01–69:01：要遵守荣誉准则；答疑时间发在 Canvas，鼓励在 Ed 上公开提问（字幕写作 Edson），作业和里程碑在 Gradescope 提交。迟交天数比较宽松，但因为这季人多不会有例外；不允许旁听，但录像最终会放上 YouTube。
